Баллистика снарядов с сопротивлением воздуха

Projectile ballistics with quadratic drag

Снаряд живёт по второму закону Ньютона: гравитация тянет вниз, воздух тормозит и сносит. Для квадратичного сопротивления аналитического решения нет — траекторию считают численным интегратором, чаще всего RK4.

дифференциальные уравненияРунге–КуттаCCD
01 Суть

Сила сопротивления растёт как квадрат скорости: Fd = ½ρCdA|v|v. На малых скоростях заметна линейная часть, но для пуль, снарядов и мячей основная — квадратичная. Ветер учитывают через относительную скорость v − w: воздух толкает снаряд в сторону своего движения, а не просто «замедляет» его.

Метод Эйлера («позиция += скорость · dt») накапливает ошибку и при больших скоростях буквально разваливает траекторию. RK4 делает четыре оценки производной на шаг и даёт локальную ошибку O(dt⁵) при цене четырёх вычислений — лучший компромисс для геймплея. Для совсем точных расчётов берут адаптивный шаг (RK45) или верlet-подобные схемы.

Для прицеливания нужна обратная задача: подобрать угол или время подрыва. Её решают симуляцией вперёд с бисекцией по углу, таблицами дальности или итеративным «баллистическим калькулятором». При скоростях выше ~300 м/с обязателен непрерывный тест столкновений (swept sphere / raycast), иначе снаряд проскочит сквозь стену между кадрами.

математическая модель
m·dv/dt = m·g − ½·ρ·Cd·A·|v − w|·(v − w)
ρ — плотность воздуха, Cd — коэффициент формы, A — площадь сечения, w — скорость ветра. Ускорение: a = g − (k/m)·|v−w|·(v−w), где k = ½ρCdA.
02 Как это построить
  1. Задайте начальные позицию, скорость, массу, Cd, площадь и вектор ветра.
  2. На каждом подшаге вычислите четыре наклона k₁…k₄ для связанной системы (p, v).
  3. Обновите скорость и позицию взвешенной суммой: y += dt/6 · (k₁ + 2k₂ + 2k₃ + k₄).
  4. Проверьте отрезок p → p′ на пересечение с коллайдерами (continuous collision detection).
  5. Для предсказания траектории прогоните ту же функцию в «теневой» симуляции без спавна эффектов и звука.
03 Рабочий код
Python 
import math

def deriv(state, wind, g, k_over_m):
    px, py, vx, vy = state
    rx, ry = vx - wind[0], vy - wind[1]
    s = math.hypot(rx, ry)
    ax = g[0] - k_over_m * s * rx
    ay = g[1] - k_over_m * s * ry
    return (vx, vy, ax, ay)

def rk4(state, dt, wind, g, k_over_m):
    k1 = deriv(state, wind, g, k_over_m)
    k2 = deriv([s + dt/2*d for s, d in zip(state, k1)], wind, g, k_over_m)
    k3 = deriv([s + dt/2*d for s, d in zip(state, k2)], wind, g, k_over_m)
    k4 = deriv([s + dt*d   for s, d in zip(state, k3)], wind, g, k_over_m)
    return [s + dt/6*(a + 2*b + 2*c + d_)
            for s, a, b, c, d_ in zip(state, k1, k2, k3, k4)]

# state = [x, y, vx, vy]; g = (0, -9.81)
# при 120 Гц: state = rk4(state, 1/120, wind=(3, 0), g=(0, -9.81), k_over_m=0.0009)

05 Где обычно ошибаются
  • Явный Эйлер при dt = 1/30 и скорости 800 м/с уводит снаряд на метры — используйте RK4 или подшаги.
  • Шаг интегрирования привязывайте к физическому тику, а рендер интерполируйте, иначе траектория «плавает» при разном FPS.
  • Cd зависит от числа Маха: табличная функция даёт правдоподобный transonic dip, один константный коэффициент — нет.
  • Точечные коллизии дают туннелирование: проверяйте свип-тест капсулы/сферы по всему отрезку перемещения.

Система крит-ударов с зависимостью от статистики

Stat-driven critical hit system

Шанс крита — не константа, а функция характеристики. Логит-модель держит вероятность в (0, 1), а пуассоновское распределение отвечает на другой вопрос: сколько критов случится за серию ударов.

распределение Пуассоналогит-модельPRD
01 Суть

Логит связывает линейную комбинацию статов с вероятностью: p = 1 / (1 + e−(β₀ + β₁·stat)). Коэффициент β₁ задаёт «цену» одного очка стата в логарифме шансов, поэтому кривая не улетает за 100 % и хорошо масштабируется на любые уровни. Обратная функция — logit(p) = ln(p/(1−p)) — удобна для дизайна: +1 к статам даёт постоянный прирост лог-шансов.

Число критов за n ударов при независимых бросках — биномиальное распределение. При большом n и малом p его приближает Пуассон: P(k) = λᵏe−λ/k!, где λ = n·p. Это позволяет оценивать «сколько критов я выдам за 20 секунд боя» и строить бюджет урона без симуляции.

Игроки болезненно воспринимают длинные серии без критов, хотя они статистически нормальны. Поэтому в соревновательных играх применяют pseudo-random distribution (PRD): шанс растёт после каждой неудачи и сбрасывается после успеха. Средняя частота остаётся заявленной, а дисперсия — ниже, ощущения — честнее.

математическая модель
p(stat) = σ(β₀ + β₁·stat), P(k) = λᵏ·e−λ / k!, λ = n·p
σ(z) = 1/(1+e−z) — сигмоида. Для PRD: pₙ = min(1, C·n) после n неудач; константу C подбирают численно так, чтобы E[число попыток] = 1/p.
02 Как это построить
  1. Соберите базовый шанс и вклад статов в лог-шансах, а не в процентах.
  2. Ограничьте вероятность разумным потолком (обычно 75–90 %) и полом.
  3. Бросьте RNG один раз на удар; критический множитель применяйте после расчёта брони.
  4. Для серийных механик оцените λ = n·p и проверьте, не выходит ли бурст за бюджет.
  5. Если жалобы на «невезучесть» — включите PRD и заново измерьте средний DPS на плейтесте.
03 Рабочий код
Python 
import math, random

def crit_chance(stat, b0=-2.2, b1=0.08):
    # β₀ задаёт базовый шанс, β₁ — силу стата
    return 1.0 / (1.0 + math.exp(-(b0 + b1 * stat)))

class PRD:
    """Pseudo-random distribution: снижает дисперсию серий."""
    def __init__(self, p, constant=0.3):
        self.p = p
        self.constant = constant   # подбирается Монте-Карло
        self.failures = 0

    def roll(self, rng=random):
        chance = min(1.0, self.constant * self.p * (self.failures + 1) ** 1.5)
        if rng.random() < chance:
            self.failures = 0
            return True
        self.failures += 1
        return False

p = crit_chance(stat=42)          # ≈ 0.66 при этих β
prd = PRD(p=0.25)

05 Где обычно ошибаются
  • «Пять ударов без крита — значит скоро будет» — ошибка игрока; PRD честно повышает шанс, чистая вероятность — нет.
  • Клиппинг вероятности в 1.0 без пересчёта бюджета урона превращает позднюю игру в крит-лотерею.
  • Суммируйте множители крита аддитивно или мультипликативно осознанно: смешение даёт неожиданные взрывы DPS.
  • RNG должен быть серверным и логируемым, иначе шанс крита — первый кандидат на эксплойт.

Динамическая генерация сбалансированных цен

Dynamic economy pricing

Цена — это сигнал о дефиците. Моделью служит вальрасовское «нащупывание»: избыточный спрос двигает цену вверх, избыточное предложение — вниз, а эластичность задаёт силу реакции.

дифференциальные уравнениятеория игрэластичность
01 Суть

Классическая динамика: dp/dt = k·(D(p) − S(p)), где D и S — функции спроса и предложения. Если считать их степенными, D(p) = D₀·(p/p₀)−ε, получаем удобную безразмерную эластичность ε: во сколько процентов меняется спрос на процент цены. Для игровой экономики важнее не точность, а устойчивость: цена обязана оставаться положительной и не колебаться вокруг равновесия бесконечно.

Второй слой — стратегическое поведение. NPC-торговцы, аукцион и перекупщики образуют игру с равновесием Нэша; если один игрок может скупить весь ресурс и взвинтить цену, сервер должен иметь контрмеры: лимиты закупки, региональные рынки, налог на перепродажу, мгновенную арбитражную комиссию. Чистая формула без институтов ломается о поведение игроков.

На практике цену обновляют не каждым кадром, а тиком рынка (раз в 30–300 секунд), с EMA-сглаживанием и ограничением относительного шага. Логарифмическая реакция p′ = p·ek·excess гарантирует положительность и делает одинаково ощутимыми рост и падение.

математическая модель
excess = (D − S) / max(D, S), p′ = p · ek·excess, p ← p + α(p′ − p)
k — скорость реакции рынка, α — сглаживание. EMA-фильтр гасит осцилляции и защищает от манипуляций одним крупным ордером.
02 Как это построить
  1. Определите источники и стоки товара: дроп, крафт, расход, налоги, порча.
  2. Постройте D(p) и S(p) с эластичностями; для NPC-продавцов задайте резервную цену.
  3. Считайте рыночный тик реже геймплея, чтобы избежать «дрожания» цен.
  4. Ограничьте изменение цены за тик (например, ±10 %) и абсолютные полы/потолки.
  5. Логируйте объём, цену и число сделок: инфляцию видно по индексу цен, а не по одной валюте.
03 Рабочий код
Python 
import math

def market_tick(price, demand, supply, k=0.15, alpha=0.25,
                floor=0.2, ceiling=5.0):
    denom = max(demand, supply, 1e-6)
    excess = (demand - supply) / denom          # ∈ [-1, 1]
    target = price * math.exp(k * excess)       # всегда > 0
    new_price = price + (target - price) * alpha
    return max(price * floor, min(price * ceiling, new_price))

# пример: дефицит толкает цену вверх плавно, без осцилляций
p = 100.0
for _ in range(5):
    p = market_tick(p, demand=120, supply=80)
    print(round(p, 2))

05 Где обычно ошибаются
  • Большой k даёт колебания цены вокруг равновесия — рынок «звенит», игроки не успевают реагировать.
  • Без стоков валюта инфлирует: цена растёт не потому, что дефицит, а потому, что денег стало больше.
  • Арбитраж между регионами нужно либо запретить, либо сделать частью геймплея с логистикой и риском.
  • Скрытые NPC-демпферы («бесконечный спрос») убивают смысл торговли — лучше явные резервы и квоты.

Плавное перемещение объектов по сплайнам

Spline paths and arc-length parameterization

Сплайн задаёт гладкую кривую через опорные точки. Главная ловушка — параметр t не пропорционален пройденному пути: без таблицы арк-длины камера и персонаж ускоряются на крутых участках.

кривые БезьеCatmull–Romарк-длина
01 Суть

Кубическая кривая Безье: B(t) = (1−t)³P₀ + 3(1−t)²tP₁ + 3(1−t)t²P₂ + t³P₃. Она лежит в выпуклой оболочке опорных точек и имеет C²-гладкость внутри сегмента, но стыки сегментов нужно специально сшивать. Catmull–Rom проходит через все точки и автоматически даёт C¹-непрерывность — поэтому его любят для трасс, камер и патрулей.

Параметр t равномерен по «формуле», но не по длине дуги. Если двигать объект как p(t + Δt), на поворотах он визуально ускоряется. Решение — таблица длин дуги: сэмплируем кривую, накапливаем расстояния, нормируем и ищем t бисекцией по нужной длине. Ещё лучше — аналитически интегрировать |B′(t)|, но LUT проще и достаточно точен (256–1024 сэмплов).

Для геймплея важны равномерная скорость, ограничение кривизны (радиус поворота) и отсутствие самопересечений. Проверяйте кривизну κ = |x′y″ − y′x″| / (x′² + y′²)3/2: слишком острый поворот ломает и камеру, и физику.

математическая модель
B(t) = Σ C(3,i)·(1−t)3−i·ti·Pᵢ, s(t) = ∫₀ᵗ |B′(u)| du
Catmull–Rom: B(t) = ½[(2P₁) + (−P₀+P₂)t + (2P₀−5P₁+4P₂−P₃)t² + (−P₀+3P₁−3P₂+P₃)t³].
02 Как это построить
  1. Задайте опорные точки и тип сплайна: Безье для дизайна, Catmull–Rom для прохождения через точки.
  2. Постройте LUT длин дуги: N сэмплов и накопленная сумма расстояний.
  3. Для движения по расстоянию s найдите t бисекцией в LUT (O(log N)).
  4. Ориентируйте объект по касательной B′(t), а крен — по кривизне и скорости.
  5. Ограничьте шаг s, чтобы на резких поворотах объект не «срезал» кривую.

Механика квантовых состояний в геймплее

Quantum state mechanics

Квантовое состояние — это вектор амплитуд, а измерение — вероятностный переход к одному из базисных состояний. В игре это даёт механику «неопределённости до наблюдения» с честной математикой.

линейная алгебраматрицы плотностисуперпозиция
01 Суть

Кубит описывается вектором |ψ⟩ = α|0⟩ + β|1⟩, где |α|² + |β|² = 1. До измерения объект «находится в суперпозиции»: например, дверь одновременно открыта и закрыта, а враг существует в двух коридорах. Измерение даёт 0 с вероятностью |α|² и 1 с вероятностью |β|², после чего состояние коллапсирует.

Смешанное состояние (когда есть классическая неопределённость) задают матрицей плотности ρ = Σ pᵢ|ψᵢ⟩⟨ψᵢ|. Гейты — унитарные матрицы: Адамар создаёт суперпозицию, CNOT запутывает два кубита. Для n кубитов вектор имеет 2ⁿ амплитуд — именно поэтому полноценный квантовый симулятор в игре ограничен 10–20 «кубитами».

Ключевое отличие от «магии»: нельзя клонировать неизвестное состояние (no-cloning), нельзя передать информацию быстрее света через запутанность (no-signaling), а сохранение/загрузка обязаны сохранять распределение, иначе игрок будет перезагружаться до нужного исхода. Поэтому сид RNG фиксируют в состоянии мира, а probabilistic-механики проектируют так, чтобы любой исход был играбелен.

математическая модель
|ψ⟩ = α|0⟩ + β|1⟩, |α|² + |β|² = 1, P(0) = |α|²
Гейт Адамара: H = 1/√2 · [[1, 1], [1, −1]]. Для двух кубитов базис: |00⟩, |01⟩, |10⟩, |11⟩; CNOT переворачивает второй при первом = 1.
02 Как это построить
  1. Выберите представление: чистые состояния (n ≤ ~12) или матрицы плотности (шум/декогеренция).
  2. Задайте унитарные гейты и их визуальные соответствия в мире.
  3. При «измерении» бросайте RNG с вероятностями из амплитуд и сохраняйте исход в состоянии объекта.
  4. Синхронизируйте seed между клиентами и сервером для детерминированного мультиплеера.
  5. Для сохранений храните амплитуды/матрицу, а не наблюдённый результат, — иначе теряется суть механики.

import math, random

# |ψ⟩ = α|0⟩ + β|1⟩, состояние — список комплексных амплитуд
def hadamard(state):
    a, b = state
    r = 1 / math.sqrt(2)
    return [r * (a + b), r * (a - b)]

def measure(state, rng=random):
    p0 = abs(state[0]) ** 2
    outcome = 0 if rng.random() < p0 else 1
    # после измерения состояние коллапсирует
    collapsed = [1.0, 0.0] if outcome == 0 else [0.0, 1.0]
    return outcome, collapsed

psi = [1.0, 0.0]          # |0⟩
psi = hadamard(psi)        # (|0⟩ + |1⟩) / √2
print(measure(psi, random.Random(42)))

ИИ для стратегических решений в 4X-играх

4X strategy AI (utility, MCTS, influence maps)

Стратегический ИИ раскладывает решение на оценку ситуации, генерацию вариантов и выбор. Utility-подход быстрее и предсказуемее, MCTS — сильнее в тактике, а влияние (influence maps) связывает карту с решениями.

utility AIMCTS/UCTдеревья решений
01 Суть

Utility AI присваивает каждому действию оценку score = Σ wᵢ·fᵢ(context), где fᵢ — нормированные факторы (нужен ли город еды, близость врага, запас золота). Выбор можно делать жадно или через softmax с температурой: высокая температура — разнообразие, низкая — детерминизм. Веса настраиваются симуляциями и теле metрией, а не вручную на глаз.

Для тактических боёв применяют MCTS с UCT: a* = argmax Q(s,a) + c·√(ln N(s)/N(s,a)). Дерево растёт в сторону перспективных веток, а rollout заменяют лёгкой эвристикой. На больших картах чистый MCTS дорог, поэтому его комбинируют с абстракцией: группы юнитов, регионы, «стратегические слои» раз в N секунд.

Influence maps — это свёртка карты по радиусам влияния юнитов и зданий. Они дают дешёвые ответы на вопросы «где мы сильны», «куда безопасно идти», «где противник откроет фронт». Слой тумана войны критичен: ИИ должен принимать решения по последней известной информации, иначе он «читерит» и играть становится неприятно.

математическая модель
score(action) = Σ wᵢ·fᵢ(ctx), P(a) = escore(a)/τ / Σ escore(b)/τ
UCT: Q(s,a) + c·√(ln N(s) / N(s,a)). Q — средняя награда, N — число посещений, c балансирует exploration/exploitation.
02 Как это построить
  1. Соберите контекст: ресурсы, угрозы, цели, туман войны, дипломатия.
  2. Опишите 10–30 действий и факторы для каждого; нормируйте факторы в [0, 1].
  3. Разделите слои: стратегия (раз в 5–30 с), тактика (раз в 0.5–2 с), микро (каждый тик).
  4. Добавьте гистерезис и cooldown, чтобы ИИ не переключался между планами каждый тик.
  5. Валидируйте поведение на реплеях: метрики «простой армии», «потерянные юниты», «время до реакции».

import math

def softmax_pick(actions, context, weights, temperature=0.35):
    scores = {}
    for name, feature_fn in actions.items():
        feats = feature_fn(context)          # {"food_need": 0.8, "threat": 0.2, ...}
        scores[name] = sum(weights[name].get(k, 0.0) * v for k, v in feats.items())
    m = max(scores.values())
    exp = {k: math.exp((v - m) / temperature) for k, v in scores.items()}
    z = sum(exp.values())
    return {k: v / z for k, v in exp.items()}

Система эмоциональных реакций NPC

Emotional NPC model (PAD + appraisal)

Эмоция NPC — точка в пространстве «удовольствие — возбуждение — доминирование», которая плавно затухает и сдвигается событиями. Такая модель даёт непрерывные реакции, а не набор скриптовых анимаций.

PAD-модельOCCкластеризация
01 Суть

Модель PAD (Pleasure, Arousal, Dominance) описывает настроение трёхмерным вектором. События оцениваются по OCC-схеме: желательность, вероятность, ожидаемость, контроль. Например, «враг украл еду» → сильное падение Pleasure, рост Arousal, падение Dominance; «я победил» → рост всех трёх при высоком контроле.

Динамика: E′ = E·λ + Σ wᵢ·eventᵢ, с затуханием к базовому характеру и клиппингом в [−1, 1]. Разные персонажи отличаются λ (скорость остывания), базовой точкой и весами оценок. Это дешево, интерпретируемо и легко тюнится дизайнером в таблице.

Сырой вектор бесполезен для анимации — его дискретизируют. Кластеризация (k-means по размеченным эмоциям: радость, страх, гнев, грусть) даёт состояние для дерева анимаций и реплик. Гистерезис и минимальная длительность перехода избавляют от «мигания» эмоций; сильные эмоции подавляют слабые, но не стирают их мгновенно.

математическая модель
E ∈ [−1,1]³ = (P, A, D), E′ = clamp(λ·E + Σ wᵢ·eventᵢ)
λ ≈ 0.9–0.99 на игровой тик. Классификация эмоции — ближайший центроид в PAD или пороги по осям.
02 Как это построить
  1. Задайте характер NPC: базовая точка PAD, скорость затухания, чувствительность к событиям.
  2. Опишите события через appraisal-признаки: желательность, контроль, ожидаемость, вина/заслуга.
  3. Обновляйте эмоцию на событии и медленно возвращайте к базовой линии.
  4. Классифицируйте состояние в набор анимаций/реплик с гистерезисом.
  5. Экспонируйте эмоцию в поведение: дистанция, агрессия, готовность торговать — игрок должен её читать.

import math

DECAY = 0.96

def appraise(emotion, event, sensitivity):
    """emotion = [P, A, D]; event = [p, a, d] в [-1, 1]."""
    out = []
    for i in range(3):
        v = emotion[i] * DECAY + event[i] * sensitivity[i]
        out.append(max(-1.0, min(1.0, v)))
    return out

EMOTIONS = {           # центроиды PAD
    "радость": (0.8, 0.6, 0.5),
    "страх":   (-0.6, 0.8, -0.7),
    "гнев":    (-0.7, 0.7, 0.6),
    "грусть":  (-0.6, -0.4, -0.4),
}

def classify(e):
    return min(EMOTIONS, key=lambda k: math.dist(e, EMOTIONS[k]))

mood = [0.0, 0.0, 0.0]
mood = appraise(mood, event=[-0.9, 0.8, -0.3], sensitivity=[0.8, 0.9, 0.5])
print(classify(mood))   # скорее всего «страх»

Адаптивная сложность противников

Adaptive difficulty (skill estimation + RL)

Цель адаптивной сложности — удержать игрока в «потоке» между скукой и фрустрацией. Сложность подбирают по оценке навыка и поведению, а не по одной полоске здоровья.

Q-learningбайесовские сетиbandit
01 Суть

Сначала нужно оценить игрока. Простейший вариант — Elo/TrueSkill-подобная оценка навыка по исходам стычек. Более информативный — байесовская сеть с признаками: точность, время реакции, число смертей, использование укрытий, темп прохождения. Апостериорное распределение навыка обновляется после каждого боя, а не «по уровню аккаунта».

Выбор сложности — это multi-armed bandit: параметры врагов (урон, агрессия, число подкреплений) — «руки», награда — близость к целевому уровню успеха (например, 60–70 % побед) плюс удержание. Thompson sampling или ε-greedy исследуют пространство, не ломая ощущение честности.

Внутри боя работает Q-learning: Q(s,a) ← Q(s,a) + α[r + γ·max Q(s′,a′) − Q(s,a)]. Награда поощряет напряжённые, но выигрываемые бои, штрафует мгновенные смерти и «мясорубку». Важно, чтобы адаптация была незаметной: игрок не должен видеть, что враги «поддаются» — иначе победа обесценивается.

математическая модель
Q(s,a) ← Q(s,a) + α·[r + γ·maxa′Q(s′,a′) − Q(s,a)]
α — скорость обучения, γ — дисконт. Для DDA награду задают как r = −|winrate − target| − λ·(смерти/время).
02 Как это построить
  1. Выберите метрику успеха: win rate, время боя, число смертей на чекпоинт, расход ресурсов.
  2. Оцените навык игрока байесовски; не смешивайте его с прогрессом снаряжения.
  3. Ограничьте пространство адаптации 3–5 параметрами, чтобы не потерять контроль баланса.
  4. Меняйте параметры ступенчато и с задержкой: резкая подстройка читается как «чит».
  5. Проверьте, что при низком навыке игра остаётся весёлой, а при высоком — не становится симулятором болванчиков.

Генерация правдоподобных диалогов

Procedural dialogue (Markov → transformers)

Диалог можно генерировать на трёх уровнях: цепь Маркова для дешёвых вариаций, грамматика для управляемого смысла и LLM для свободной речи. В игре почти всегда нужен гибрид с жёсткими ограничениями.

цепи Марковатрансформерыграмматики
01 Суть

Цепь Маркова первого порядка хранит вероятности перехода между словами: P(wₜ | wₜ₋₁). Обучение — просто подсчёт пар, генерация — случайное блуждание по графу. Это дёшево и даёт «правдоподобный шум», но связность короткая: через 10–15 слов модель забывает начало. Для имён и коротких реплик этого часто достаточно.

Современный подход — трансформер с механизмом внимания: Attention(Q,K,V) = softmax(QKᵀ/√dk)V. Модель учитывает весь контекст, но требует токенов, памяти и задержки. В играх применяют маленькие локальные модели (1–8B параметров), кэш KV, потоковую генерацию и ограничение длины. Качество резко растёт, если дать модели структурированный контекст: кто говорит, отношения, известные факты, текущий квест.

Продакшн-схема: авторский граф диалога задаёт ветки и последствия, а LLM перефразирует реплики внутри узла с ограничениями (тон, длина, запрещённые темы, факты мира). Валидация ответов, fallback на шаблон и логирование обязательны: генеративный текст без гардрейлов ломает лор и рейтинг.

математическая модель
P(w₁…wₙ) = Π P(wₜ | wₜ₋₁), Attention(Q,K,V) = softmax(QKᵀ/√dk)·V
Для триграмм: P(wₜ | wₜ₋₂, wₜ₋₁). Температура T делит логиты перед softmax: выше T — разнообразнее, ниже — стабильнее.
02 Как это построить
  1. Определите границы свободы: имена/реплики/ветки — что можно генерировать, что нельзя.
  2. Соберите корпус в голосе персонажа или задайте грамматику с слотами.
  3. Добавьте состояние: отношения, память о событиях, текущая цель — иначе диалог бессмысленный.
  4. Ограничьте длину и проверяйте факты по базе знаний; при провале — шаблонный fallback.
  5. Логируйте и модерайте выходы, особенно в мультиплеере и UGC.

Оптимизация группового поведения юнитов

Flocking / boids and crowd steering

Три простых правила — держать дистанцию, выравнивать скорость, тянуться к центру — дают убедительную стаю. Секрет не в правилах, а в пространственном индексе и ограничении сил.

теория рояboidsspatial hash
01 Суть

Boids Рейнольдса: separation (отталкивание от близких), alignment (совпадение направления с соседями), cohesion (притяжение к центру группы). Каждое правило даёт вектор, они смешиваются с весами и ограничиваются по модулю. Разные радиусы для правил критичны: separation — короткий, cohesion — длинный.

Наивное «каждый с каждым» — O(n²), для 500 юнитов это 250 000 проверок на кадр. Пространственный хэш (сетка с ячейкой ~ радиусу) снижает до O(n·k), где k — среднее число соседей. Для тысяч агентов на GPU считают в compute-шейдере или используют flow fields для дальнего перемещения.

Поверх boids кладут steering behaviors: избегание препятствий, преследование, удержание формации, очередь/толпа у двери. Ограничение максимальной силы и скорости (clamp), а также приоритеты (separation важнее cohesion) предотвращают дрожание и «взрывы» плотности. Для детерминированного мультиплеера обновление должно идти фиксированным тиком и без зависимости от порядка итерации.

математическая модель
v ← clamp(v + Σ wᵢ·steerᵢ·dt, vmax), steersep = Σ (p − pⱼ)/|p − pⱼ|²
Соседство обычно ограничивают радиусом и углом обзора (например, 270°), иначе стая «видит» за спиной.
02 Как это построить
  1. Постройте пространственный хэш по позициям агентов раз в тик.
  2. Для каждого агента соберите соседей в радиусе восприятия.
  3. Вычислите три силы, нормируйте и смешайте с весами; separation дайте приоритет.
  4. Ограничьте ускорение и скорость; добавьте демпфирование, чтобы стая успокаивалась.
  5. Добавьте препятствия и «лидеров» (flow field или цель), иначе стая будет кружить на месте.

def neighbors_hash(agents, cell):

    for a in agents:

    sep_x = sep_y = ali_x = ali_y = coh_x = coh_y = 0.0
    n = 0
    cx, cy = int(b["x"] // cell), int(b["y"] // cell)
    for gx in (cx-1, cx, cx+1):
        for gy in (cy-1, cy, cy+1):
            for o in grid.get((gx, gy), ()):

Процедурная генерация реалистичных ландшафтов

Procedural terrain with fBm and erosion

Ландшафт — это сумма октав шума: крупные формы задают горы, мелкие — камни. Реализм появляется, когда к шуму добавляют эрозию, биомы и ограничения проходимости.

шум Перлинафракталыэрозия
01 Суть

Фрактальный броуновский шум (fBm): h(x) = Σ aᵢ·noise(fᵢ·x), где каждая октава удваивает частоту и уменьшает амплитуду. Перлин даёт градиентный шум без «квадратности» value-noise, а ridged-вариант (1 − |noise|)² создаёт горные хребты. Domain warping — смещение координат другим шумом — добавляет извилистые долины и неестественно красивые формы.

Сырой шум выглядит «пушистым», но не похож на землю. Гидравлическая эрозия моделирует капли воды: капля скатывается по градиенту, размывает грунт, переносит наносы и откладывает их в низинах. Несколько сотен тысяч капель на карту дают долины, конусы выноса и русла рек. Альтернатива для реального времени — пре-бейк эрозии в текстуру и использование её как маски.

Биомы задают по температуре и влажности: высота + широта → температура, удалённость от воды + ветер → влажность. Далее правила: пустыня, лес, тундра, болото. Важна игровая валидация: карта должна иметь связные проходимые пути, стартовые зоны с ресурсами и естественные границы. Чанки генерируются с LOD, а шум сэмплируется в мировых координатах — иначе на стыках появятся швы.

математическая модель
fBm(x) = Σi=0O−1 gaini·noise(x·lacunarityi)
Типично: O = 4–8 октав, lacunarity = 2, gain = 0.5. Ridged: (1 − |noise|)² усиливает хребты.
02 Как это построить
  1. Сгенерируйте базовую высоту fBm в мировых координатах с сидом.
  2. Добавьте горные хребты ridged-шумом и warping для долин.
  3. Прогоните эрозию (офлайн или на GPU) и сохраните карту наносов.
  4. Вычислите температуру/влажность и разметьте биомы.
  5. Проверьте связность и стартовые зоны; постройте навигационный меш и LOD-чанки.

import math

def fbm(x, y, noise2, octaves=6, lacunarity=2.0, gain=0.5):
    amp, freq = 1.0, 1.0
    total = norm = 0.0
    for _ in range(octaves):
        total += amp * noise2(x * freq, y * freq)
        norm += amp
        amp *= gain
        freq *= lacunarity
    return total / norm          # нормировано в [-1, 1]

def terrain_height(x, y, noise2, sea=0.0):
    base = fbm(x, y, noise2) * 0.5 + 0.5
    ridge = 1.0 - abs(fbm(x * 2.1, y * 2.1, noise2, 4))
    h = base * 0.75 + ridge * 0.25
    return max(0.0, h - sea) ** 1.6   # приподнятые горы, плоские низины

Динамическое глобальное освещение

Dynamic global illumination

Глобальное освещение — это интеграл по всем направлениям, учитывающий свет, отражённый от других поверхностей. В реальном времени его считают приближённо: пробы, трассировка лучей с шумоподавлением или запечённые lightmap.

уравнение рендерингаradiositypath tracingDDGI
01 Суть

Уравнение рендеринга: Lo(x, ωo) = Le + ∫ fr(x, ωi, ωo)·Li(x, ωi)·cosθi dωi. Оно рекурсивно: Li — это исходящий свет с других поверхностей. Аналитически решается только для простых сцен; численно — Монте-Карло оценкой выборок.

Path tracing оценивает интеграл как среднее по лучам: L ≈ (1/N)·Σ f·L·cosθ / pdf. Для Lambertian-материала f = albedo/π, pdf = cosθ/π, и множители сокращаются до albedo — поэтому оценка такая элегантная. Проблема — шум: чтобы его убрать, нужны денойзер (SVGF, OIDN) и временнáя аккумуляция с репроекцией.

Альтернативы для реального времени: запечённые lightmap и irradiance probes (статический свет), DDGI — сетка проб с обновлением лучей и шариковыми гармониками, screen-space GI (дешёво, но не видит за экраном), Lumen-подобные гибриды с SDF-сценой. Radiosity (метод излучательности) решает систему линейных уравнений для диффузных поверхностей и до сих пор используется для запекания.

математическая модель
Lo = Le + ∫Ω fr·Li·cosθi dωi
Для диффузной поверхности: Lo = Le + (albedo/π)·∫ Li cosθ dω. Итерации radiosity сходятся к решению системы форм-факторов.
02 Как это построить
  1. Определите бюджет: запечённый свет, зонды или полноценный трассировщик лучей.
  2. Разделите прямой и непрямой свет: прямой — тени/карты, непрямой — пробы или лучи.
  3. Для path tracing добавьте важностную выборку (NEE) и денойзер.
  4. Для DDGI обновляйте пробы порциями по кадрам и храните SH-коэффициенты.
  5. Следите за утечками света (light leaks) и смещением теней; настраивайте bias.

import math

def basis(n):
    helper = (0.0, 1.0, 0.0) if abs(n[1]) < 0.99 else (1.0, 0.0, 0.0)
    t = normalize(cross(helper, n))
    return t, cross(n, t)

def cosine_hemisphere(n, rng):
    u1, u2 = rng.random(), rng.random()
    r, phi = math.sqrt(u1), 2 * math.pi * u2
    tangent, bitangent = basis(n)      # ортонормированный базис вокруг n
    cos_t, sin_t = math.cos(phi), math.sin(phi)
    return tuple(tangent[i] * (r * cos_t) + bitangent[i] * (r * sin_t)
                 + n[i] * math.sqrt(max(0.0, 1.0 - u1)) for i in range(3))

def radiance(ray, depth, scene, rng):
    hit = scene.intersect(ray)
    if hit is None:
        return scene.sky(ray.direction)
    if depth == 0:
        return hit.emission
    wi = cosine_hemisphere(hit.normal, rng)
    # f_r = albedo/π, pdf = cosθ/π  =>  f_r·cosθ/pdf = albedo
    return hit.emission + hit.albedo * radiance(
        hit.spawn(wi), depth - 1, scene, rng)

Система разрушения объектов

Destruction: stress, Voronoi, rigid bodies

Разрушение — это сравнение напряжения с прочностью материала. Чтобы оно было играбельным, фрагменты почти всегда готовят заранее (Voronoi), а в рантайме только выбирают, какой кусок отколоть.

теория упругостиMКЭVoronoi
01 Суть

Напряжение σ = F/A, деформация ε = ΔL/L, закон Гука σ = E·ε. Когда напряжение превышает предел прочности, материал трескается. Для хрупких объектов (стекло, бетон) важна не только сила, но и направление удара; для металлов — пластическая деформация. Полноценный МКЭ в реальном времени слишком дорог, поэтому физику упрощают до жёстких тел и заранее нарезанных фрагментов.

Voronoi-нарезка: в объёме объекта генерируют точки, затем каждая точка «забирает» ближайший объём. Получается мозаика выпуклых осколков, которые идеально стыкуются. Заранее создают несколько уровней детализации (крупные куски → мелкие), а при ударе активируют нужный. Связность проверяют обходом графа соседних фрагментов: оторванные куски должны улететь, а не висеть в воздухе.

Рантайм-бюджет: ограничение числа активных rigidbody, засыпание (sleeping) после остановки, слияние мелких осколков в декали и пыль, LOD для дальних обломков. В мультиплеере разрушение должно быть или серверным, или детерминированным по сиду — иначе клиенты увидят разные стены.

математическая модель
σ = E·ε, разрушение при σ > σmax, Eудар = ½mv²

02 Как это построить
  1. Разметьте объект на «структурные» и «декоративные» части; у первых задайте прочность.
  2. Заранее нарежьте объект Voronoi-фрагментами с 2–3 уровнями детализации.
  3. Постройте граф соседства фрагментов для проверки связности после удара.
  4. В момент удара сравните энергию/напряжение с порогом и активируйте осколки.
  5. Ограничьте число активных тел и замените мелкие обломки партиклами/декалями.

Реализация реалистичной воды

Water rendering with FFT waves and SPH

Вода в игре — это два разных алгоритма: поверхность океана (сумма волн, FFT, отражения) и объём/взаимодействие (SPH или height field). Смешивать их в одной системе дорого, поэтому почти всегда разделяют.

Навье–СтоксаSPHFFT-волны
01 Суть

Уравнения Навье–Стокса для несжимаемой жидкости: ∂u/∂t + (u·∇)u = −∇p/ρ + ν∇²u + f, ∇·u = 0. Прямое решение на сетке в реальном времени возможно лишь для маленьких объёмов. Для океана используют спектральный подход: сумма синусоид с дисперсией глубокой воды ω² = g·k, где k — волновое число. FFT по спектру Филлипса даёт карту высот и нормалей на 256×256 за миллисекунды на GPU.

SPH (Smoothed Particle Hydrodynamics) представляет жидкость частицами с ядром сглаживания W: плотность ρᵢ = Σ mⱼW(rᵢⱼ, h), давление по уравнению состояния p = k(ρ − ρ₀). Силы давления и вязкости толкают частицы, а границы обрабатывают штрафными силами. SPH отлично подходит для брызг, водопадов и луж, но требует подшагов и даёт шумную поверхность — её восстанавливают через marching cubes или screen-space fluid.

Рендер воды: френелевское отражение F(θ) = F₀ + (1−F₀)(1−cosθ)⁵, преломление с искажением по нормали, глубинное поглощение по закону Бера (цвет зависит от расстояния), пена по порогу высоты/скорости и каустики как проецируемая текстура. Без Fresnel и глубинного тумана вода выглядит как синий пластик.

математическая модель
∂u/∂t + (u·∇)u = −∇p/ρ + ν∇²u + f, ∇·u = 0, ω² = g·k
SPH: ρᵢ = Σⱼ mⱼ·W(|rᵢ−rⱼ|, h), pᵢ = k·(ρᵢ − ρ₀). Fresnel: F = F₀ + (1−F₀)(1−cosθ)⁵.
02 Как это построить
  1. Выберите модель: FFT-волны для открытого океана, height field для рек, SPH для брызг и объёма.
  2. Для океана сгенерируйте спектр, выполните IFFT для высот и нормалей, добавьте мелкую рябь нормал-мапой.
  3. Для SPH настройте h, массу, жёсткость и число подшагов; стабилизируйте давление (PCISPH/DFSPH).
  4. Рендерите с Fresnel, преломлением и поглощением по глубине; добавьте пену по скорости.
  5. Синхронизируйте фазы волн по сети или считайте их чисто визуальными на клиенте.

// Gerstner-волна: смещение по вертикали и горизонтали
vec3 gerstner(vec2 p, vec2 dir, float steepness, float wavelength,
              float speed, float t, out vec3 normal)
{
    float k = 6.28318 / wavelength;
    float c = sqrt(9.81 / k);          // фазовая скорость
    float f = k * (dot(dir, p) - c * speed * t);
    float a = steepness / k;
    normal = vec3(-dir.x * steepness * cos(f),
                  1.0 - steepness * sin(f),
                  -dir.y * steepness * cos(f));
    return vec3(dir.x * a * cos(f), a * sin(f), dir.y * a * cos(f));
}

Генерация объёмных облаков

Volumetric clouds and ray marching

Облако — это поле плотности в объёме. Луч проходит через него шагами, накапливая рассеянный свет; ключ к качеству — функция плотности (fBm с erosion) и дешёвая аппроксимация освещения.

ray marchingфункции плотностиBeer–Lambert
01 Суть

Плотность задают 3D-шумом: ρ(x) = smoothstep(threshold, threshold + w, fbm(x)) с высотным градиентом и «погодной картой» на земле. Чтобы облака были пушистыми, из базовой формы вычитают более высокочастотный шум (erosion) — это дешевле и красивее, чем один шум с большим числом октав.

Ray marching: вдоль луча берут N шагов, на каждом оценивают плотность и накапливают прозрачность по закону Бера–Ламберта T = exp(−∫σ·ds). Свет в точке оценивают «дешёвым» вторым маршем к солнцу (6–8 шагов) с фазовой функцией Хеньи–Гринстейна для серебристой каймы. Полный марш к солнцу на каждом шаге слишком дорог, поэтому используют предвычисленные карты освещения или аппроксимацию по глубине.

Оптимизации: пустой пробел (empty space skipping) по мип-пирамиде плотности, jitter стартового смещения для сглаживания бандинга, временнáя аккумуляция с репроекцией, blue-noise дизеринг. Облака — классический пример, где 32 шага с хорошим шумом выглядят лучше 128 шагов с плохим.

математическая модель
T = exp(−∫ σt(x) ds), L = ∫ σs(x)·T(x)·Lsun·phase(θ) ds
Phase HG: P(θ) = (1−g²) / (4π(1 + g² − 2g·cosθ)3/2), g ≈ 0.6–0.8 для прямого рассеяния.
02 Как это построить
  1. Сгенерируйте 3D-текстуру плотности: базовая форма + erosion-шум, с высотным затуханием.
  2. Постройте мип-пирамиду плотности для пустого пробела.
  3. В шейдере выполните ray march с дизерингом старта и адаптивным шагом.
  4. Оценивайте освещение по направлению к солнцу коротким маршем или по карте.
  5. Аккумулируйте результат между кадрами с репроекцией и обрезайте историю при смене камеры.

Предсказание движения в FPS

Client-side prediction and interpolation

Сеть приносит задержку, поэтому клиент показывает движение раньше сервера: предсказывает свои действия локально и интерполирует чужие. Расхождение исправляется мягкой коррекцией, а не телепортом.

фильтр Калманаэкстраполяцияrollback
01 Суть

Классическая схема: input → клиент применяет движение немедленно (prediction) → сервер авторитетно пересчитывает → клиент сравнивает и корректирует. Храните кольцевой буфер входов и состояний; при получении снапшота сервера пересимулируйте с последнего подтверждённого тика (rollback). Так работает Quake/Source и большинство шутеров.

Для чужих игроков используйте интерполяцию с задержкой ~100–150 мс: показывайте прошлое, но гладко. Экстраполяция (продолжение скорости) помогает при потере пакетов, но при резкой смене направления даёт «резиновых» противников. Фильтр Калмана даёт оптимальную оценку позиции и скорости с учётом шума измерений: x̂ₖ = x̂ₖ⁻ + K(zₖ − Hx̂ₖ⁻), где K зависит от соотношения шума процесса и измерения.

Сглаживание ошибки: смещение позиции и угла затухает экспоненциально (обычно 100–200 мс), а не мгновенно. Для стрельбы используют lag compensation — сервер откатывает попадания к моменту выстрела клиента, иначе при пинге 80 мс стрелять по движущимся целям невозможно. Всё это требует синхронизированных часов и стабильного тика.

математическая модель
x̂ₖ = x̂ₖ⁻ + K·(zₖ − H·x̂ₖ⁻), K = P⁻Hᵀ(HP⁻Hᵀ + R)⁻¹
Модель: xₖ = F·xₖ₋₁ + w, zₖ = H·xₖ + v. Для позиции+скорости F = [[1, dt], [0, 1]], H = [1, 0].
02 Как это построить
  1. Зафиксируйте тик сервера (например, 30–60 Гц) и протокол снапшотов.
  2. Клиент применяет свой ввод сразу и хранит (тик, ввод, состояние) в буфере.
  3. При снапшоте найдите подтверждённый тик, скорректируйте состояние и пересимулируйте вводы.
  4. Чужих игроков рендерите с задержкой и интерполяцией; экстраполяцию включайте только на потерю пакетов.
  5. Сглаживайте визуальную ошибку и отключайте prediction для телепортов/смерти.

Система защиты от читеров

Anti-cheat: statistical anomaly detection

Античит — это многослойная система: авторитетный сервер, статистическая детекция аномалий, проверка клиента и экономика банов. Z-score ловит выбросы, но требует осторожности с ложными срабатываниями.

z-scoreаномалиидоверие
01 Суть

Базовая гигиена: сервер никогда не доверяет клиенту позицию, урон и ресурсы. Клиент отправляет ввод, сервер — результат. Для особо чувствительных данных используют «туман войны» на сервере: клиент не получает позиции врагов, которые не видны. Это устраняет целый класс wallhack-читов без всякой статистики.

Статистика: для каждого игрока считают метрики — доля попаданий в голову, время реакции, точность на больших дистанциях, распределение углов прицеливания. Z-score z = (x − μ)/σ показывает, насколько метрика отклонилась от популяции. Но на миллионов игроков найдутся десятки честных «выбросов», поэтому используют робастные оценки (медиана/MAD), комбинации метрик и байесовские priors, а не один порог.

Обнаружение невозможно без реакции: реплеи подозрительных матчей, shadow bans (подозреваемый попадает в отдельный пул), постепенные баны волнами, апелляции. Клиентские античиты (подпись, целостность памяти) повышают стоимость читов, но не дают гарантий; kernel-level решения — предмет отдельного спора о приватности. Метрика успеха — не «поймали всех», а «честным играть комфортно».

математическая модель
z = (x − μ)/σ, робастно: z′ = 0.6745·(x − median)/MAD
MAD = median(|x − median(x)|). Порог |z′| > 3.5 — классический критерий выброса для нормальных данных.
02 Как это построить
  1. Закройте базовые дыры: серверный авторитет, валидация ввода, туман войны на сервере.
  2. Соберите телеметрию: попадания, задержки, углы, движения, экономика — с привязкой к матчу.
  3. Постройте робастные распределения по скилловым бакетам, а не по всей базе.
  4. Комбинируйте сигналы (score fusion) и отправляйте на ручной/ML-разбор только верхние перцентили.
  5. Действуйте волнами, сохраняйте доказательства, обеспечьте апелляцию и не раскрывайте пороги.

import statistics as st

def robust_z(x, population):
    med = st.median(population)
    mad = st.median([abs(v - med) for v in population]) or 1e-9
    return 0.6745 * (x - med) / mad

def suspicious(player, population):
    signals = {
        "headshot_rate": robust_z(player["hs"], population["hs"]),
        "snap_angle":    robust_z(player["snap"], population["snap"]),
        "reaction_ms":  -robust_z(player["react"], population["react"]),
    }
    # требуем согласия нескольких сигналов, а не одного выброса

Детерминированная симуляция RTS

Deterministic lockstep simulation

RTS передаёт не состояние мира, а команды игроков: все клиенты считают одинаковую симуляцию и получают одинаковый результат. Это требует строгого детерминизма — целочисленной математики и фиксированного порядка обновлений.

fixed-pointдетерминизмlockstep
01 Суть

Lockstep: каждый тик клиенты отправляют команды, ждут команды всех участников и только потом считают следующий тик. Трафик минимален (единицы килобайт на матч), реплей — это просто лог команд. Цена — задержка равна самому медленному игроку, и любое расхождение (desync) ломает матч.

Детерминизм требует: фиксированного шага (например, 20 тиков/с), целочисленной или fixed-point арифметики (Q16.16), одинакового порядка итерации контейнеров, одинаковой реализации RNG (xorshift с сохранённым состоянием), отсутствия зависимости от времени кадра и порядка хэш-таблиц. Float в разных компиляторах/CPU может дать разные биты — отсюда классические desync-баги.

Проверка: каждый клиент считает хэш состояния (CRC/FNV) каждые N тиков и сравнивает. При расхождении сохраняют состояние и реплей для разбора. Для ускорения используют «шардинг» симуляции и параллельные вычисления с фиксированным порядком слияния, а для сглаживания — интерполяцию между тиками и предсказание своих юнитов.

математическая модель
xQ16.16 = round(x·216), a·b → (a·b) >> 16, hash = FNV-1a(state)
Тик: 20–30 Гц. Команды применяются на тике T + задержка, одинаково у всех.
02 Как это построить
  1. Зафиксируйте тик и запретите любую зависимость симуляции от реального времени.
  2. Переведите игровую математику на fixed-point/целые; отдельно проверьте тригонометрию и sqrt.
  3. Сделайте RNG частью состояния мира и сохраняйте его в хэш.
  4. Сортируйте все обходы (сущности, коллизии, таймеры) по стабильному ключу.
  5. Сравнивайте хэши между клиентами и храните реплеи для отладки desync.

Оптимизация передачи состояния мира

Snapshot compression and delta encoding

Сеть дорога, поэтому передают не «весь мир», а изменения: дельты, квантованные значения и битовые маски. Теория информации задаёт нижнюю границу — и подсказывает, где терять точность безопасно.

энтропия Шеннонаквантованиедельта
01 Суть

Энтропия Шеннона H(X) = −Σ p(x)·log₂ p(x) — среднее число бит на символ при оптимальном кодировании. Если позиция юнита имеет 1024 возможных значения, нужно 10 бит, а не 32. Квантование позиции до 1 см и поворота до 1° экономит в 3–4 раза при незаметной для глаза потере точности.

Дельта-кодирование: передаём только поля, изменившиеся с подтверждённого снапшота, плюс битовую маску изменений. Baseline — последний подтверждённый снапшот, а не предыдущий отправленный, иначе потеря пакета ломает всю цепочку. Дополнительно: change-of-basis (позиция относительно опорной точки), priority/areas of interest (близкие объекты — чаще и точнее), и сжатие пачки (zstd/lz4).

Бюджет: цельтесь в 10–30 КБ/с на игрока для шутера и 2–5 КБ/с для RTS. Считайте не только средний битрейт, но и хвост (99-й перцентиль) — именно хвост вызывает лаги. Оценивайте выгоду каждого поля по формуле «биты × частота изменения»; чаще всего 80 % трафика — позиции и повороты.

математическая модель
H = −Σ pᵢ·log₂ pᵢ, bits ≈ log₂(диапазон/шаг)
Позиция в диапазоне 0–1024 м с шагом 0.01 м → 17 бит вместо 32. Кватернион — 3 компоненты по 10–12 бит (smallest-three).
02 Как это построить
  1. Инвентаризируйте поля состояния и их частоту изменения.
  2. Квантуйте с допуском, незаметным для игрока (см. масштаб сцены и скорость).
  3. Стройте дельту от подтверждённого baseline и передавайте битовую маску.
  4. Приоритизируйте объекты по видимости/расстоянию (AOI) и обновляйте их с разной частотой.
  5. Измеряйте 99-й перцентиль размера снапшота и потерь, а не только среднее.

import math

def quantize(value, min_v, max_v, bits):
    levels = (1 << bits) - 1
    t = (value - min_v) / (max_v - min_v)
    q = max(0, min(levels, int(round(t * levels))))
    return q

def dequantize(q, min_v, max_v, bits):
    levels = (1 << bits) - 1
    return min_v + (q / levels) * (max_v - min_v)

def delta(baseline, current, mask_fields):
    bits = 0
    changed = []
    for name, mask in mask_fields.items():
        if baseline.get(name) != current.get(name):
            bits += mask
            changed.append(name)
    return changed, bits

def entropy(counts, total):
    return -sum((c/total) * math.log2(c/total) for c in counts if c)

Создание уникальных планетарных систем

Procedural planetary systems

Планетная система — это иерархия орбит, где масса звезды задаёт масштаб времён, а радиус орбиты — климат. Для геймплея достаточно кеплеровских орбит и разумных правил распределения, а не полной n-body симуляции.

законы Кеплераn-bodyзоны обитаемости
01 Суть

Третий закон Кеплера: T² = 4π²a³/(G(M+m)). Он связывает период и большую полуось, поэтому систему удобно генерировать в единицах «астрономических единиц и лет»: для звезды солнечной массы T(годы) = a(AU)1.5. Уравнение Кеплера M = E − e·sin E решают итерациями Ньютона, чтобы получить истинную аномалию и позицию на эллипсе.

Правила правдоподобия: орбиты почти компланарны (±5°), периоды кратны друг другу в резонансах (2:1, 3:2), газовые гиганты — дальше от звезды, скалистые — ближе, зона обитаемости на радиусе, где поток ≈ земному. Полная n-body симуляция для геймплея избыточна и хаотична; её применяют для спецэффектов, а не для стабильных орбит.

Климат: поток от звезды F = L/(4πa²), равновесная температура T ≈ 278·(L/L☉)1/4/√(a/AU) К. Далее альбедо, парниковый эффект, приливы и осевой наклон. Для визуала: отрисовка орбит с масштабом логарифма, чтобы дальние планеты не улетали за экран, но подписи сохраняли реальные периоды.

математическая модель
T² = 4π²a³ / (G(M+m)), M = E − e·sin E, F = L/(4πa²)
T в секундах, a в метрах, M в кг. В игровых единицах удобно: T(лет) ≈ √(a(AU)³/M(M☉)).
02 Как это построить
  1. Задайте звезду: масса, светимость, спектральный класс, возраст.
  2. Разместите планеты по лог-равномерному распределению полуосей с запретом пересечений.
  3. Добавьте эксцентриситеты и наклоны, проверьте устойчивость на 10⁴ орбит.
  4. Вычислите поток и температуру, назначьте биом/атмосферу.
  5. Постройте визуализацию с масштабом и подписями; симуляцию орбит считайте аналитически.

Генерация сбалансированных карт для стратегий

Balanced strategy map generation

Баланс карты — это не «одинаковые стартовые зоны», а равенство возможностей: связность, расстояние до ресурсов, число входов и оборонительная ценность. Проверять это нужно графами и метриками.

теория графовсимметрияфэйрнесс
01 Суть

Сначала генерируют геометрию (шум, регионы, реки), затем строят граф связности проходимых зон: узлы — области, рёбра — проходы между ними, веса — стоимость пути. Дальше карта оценивается метриками: диаметр графа, радиус от стартов до ресурсов, число «узких мест» (артикуляций), доля проходимой площади, симметрия по осям/повороту.

Симметрия бывает зеркальной (point symmetry — поворот на 180°, как в большинстве RTS), осевой и rotational. Она гарантирует равные расстояния и одинаковые тайминги, но делает карты предсказуемыми. Асимметричные карты интереснее, но требуют компенсации: разные ресурсы, разная защита, разная скорость расширения — и проверки, что ни одна сторона не имеет преимущества первого хода.

Валидация: запуск тысяч матчей ботов на сгенерированных картах, winrate по расам/слотам, время до первого контакта, доступ к критическим ресурсам. Карта, где один старт имеет 3 входа, а другой 1, — сломанная, даже если выглядит красиво. Часто проще генерировать половину и зеркалить, чем пытаться балансировать асимметрию эвристиками.

математическая модель
fairness = Σ wᵢ·|metric(startᵢ) − mean(metrics)|, между стартами → 0
Метрики: расстояние до ближайших ресурсов, до центра, число проходов, площадь «своей» территории, время до ключевых точек.
02 Как это построить
  1. Сгенерируйте рельеф и ресурсы с сидом, выделите проходимые области.
  2. Постройте граф связности и проверьте, что все старты в одной компоненте.
  3. Разместите старты симметрично или с компенсацией по метрикам.
  4. Посчитайте fairness-метрики и отбракуйте карты с выбросами.
  5. Прогоните ботов и телеметрию winrate; при дисбалансе — правьте правила, а не отдельные карты.

from collections import deque

def bfs_dist(graph, start):
    dist, q = {start: 0}, deque([start])
    while q:
        u = q.popleft()
        for v, w in graph[u]:
            if v not in dist:
                dist[v] = dist[u] + w
                q.append(v)
    return dist

def fairness(graph, starts, resources):
    scores = {}
    for s in starts:
        d = bfs_dist(graph, s)
        reachable = [d[r] for r in resources if r in d]
        scores[s] = sum(sorted(reachable)[:3]) / 3   # 3 ближайших ресурса
    mean = sum(scores.values()) / len(scores)
    spread = max(abs(v - mean) for v in scores.values())
    return mean, spread          # spread — мера дисбаланса

Построение правдоподобных экосистем

Lotka–Volterra ecosystems

Экосистема — это система дифференциальных уравнений «хищник–жертва» и правила трофической сети. Простые уравнения дают циклы, но для игры важнее стабильность, а не математическая красота.

Лотка–Вольтеррадинамические системытрофические сети
01 Суть

Базовая модель: dx/dt = αx − βxy (жертва), dy/dt = δxy − γy (хищник). Решение — замкнутые циклы вокруг равновесия: численность колеблется, не затухая. В игре это выглядит как «волны» популяций, но на практике численность уходит в ноль из-за дискретности и случайности. Поэтому добавляют ёмкость среды (логистический рост) и шум.

Логистика: dx/dt = αx(1 − x/K) − βxy. С ёмкостью K система получает устойчивый фокус или предельный цикл. Для трёх и более видов возможны хаос и вымирания; чтобы экосистема не умерла, применяют «иммиграцию» (спавн из пула), убежища (жертвы прячутся), сезонность и ограничение хищников снизу/сверху.

Для геймплея удобнее дискретная модель на тик: x′ = clamp(x + (births − deaths − predation)·dt) с целочисленными особями. Моделируйте не каждого волка, а популяции, а поведение особей — отдельно (boids/FSM). Игрок должен видеть причинно-следственную связь: убили оленей — волки пошли к деревне; иначе симуляция не читается.

математическая модель
dx/dt = αx(1 − x/K) − βxy, dy/dt = δxy − γy
α — рождаемость жертвы, β — эффективность хищника, δ — конверсия биомассы, γ — смертность хищника, K — ёмкость среды.
02 Как это построить
  1. Определите виды и трофические связи; начните с 3–5 видов, не больше.
  2. Задайте параметры так, чтобы равновесие было устойчивым при разумных начальных условиях.
  3. Добавьте стохастику, сезонность и иммиграцию, чтобы избежать вымирания в ноль.
  4. Дискретизируйте по тику и ограничьте значения; следите за численностью на длинных прогонах.

Процедурные музыкальные композиции

Procedural music with L-systems

Музыка генерируется на двух уровнях: структура (формы, секции) — грамматиками и L-системами, а ноты — марковскими цепями по ладу и гармонии. Ограничения теории музыки делают случайность осмысленной.

L-системытеория музыкимарковские цепи
01 Суть

L-система — это параллельная переписывающая грамматика: аксиома разворачивается по правилам N раз, затем символы интерпретируются как музыкальные события. Например, F → F+G, G → F−G порождает самоподобные ритмические фигуры. В отличие от простого random, L-системы дают структуру с повторениями и вариациями — то, что мозг воспринимает как музыку.

Гармония: выбирайте аккорды из лада по функциональной логике (тоника–субдоминанта–доминанта) или по марковской цепи, обученной на корпусе. Мелодия — случайное блуждание по аккордовым тонам с тяготением к устойчивым ступеням; сильные доли — тоны аккорда, слабые — проходящие. Ритм задают деревья или евклидовы ритмы (E(5,8) — «кубинский» рисунок).

Для адаптивной музыки (vertical remixing) треки разбивают на слои: бас, гармония, мелодия, перкуссия. Громкость слоёв привязана к интенсивности геймплея, а темп и тональность синхронизированы. Важна бесшовность: переходы по тактам, а не по случайным моментам, и «stinger»-фразы для событий.

математическая модель
A → B, B → A+B (L-система), P(notei | notei−1, chord)
Евклидов ритм E(k, n): k ударов, распределённых максимально равномерно по n шагам: floor(i·k/n) меняется → удар.
02 Как это построить

  2. Сгенерируйте ритмический паттерн (евклидов ритм или L-система).
  3. Сгенерируйте прогрессию аккордов по функциональной логике/марковской цепи.
  4. Постройте мелодию по аккордовым тонам с ограничением интервалов и диапазона.
  5. Свяжите интенсивность слоёв с геймплеем и переключайте секции по границам тактов.

Реализация ткани и мягких тел

Cloth and soft bodies (Verlet, XPBD)

Ткань — это сетка частиц, связанных ограничениями длины. Verlet даёт бесплатное демпфирование и простую реализацию, а XPBD добавляет стабильность при жёстких ограничениях.

масс-пружиныинтегрирование ВерлеXPBD
01 Суть

Verlet без явной скорости: x′ = 2x − xprev + a·dt². Позиция обновляется из двух предыдущих, скорость неявная — это делает схему устойчивой и позволяет легко накладывать ограничения прямо на позиции. Ограничение «расстояние между частицами равно L» решается проекцией: сдвигаем обе точки вдоль соединяющей линии на долю ошибки. 10–20 итераций дают жёсткую, но не «взрывающуюся» ткань.

Масс-пружинная модель с жёсткими пружинами требует крошечного dt или имплицитного интегрирования. Поэтому для ткани и верёвок используют constraint-based подход (PBD/XPBD), где жёсткость выражается через податливость α, а не через огромный коэффициент k. XPBD: Δλ = (−C − α̃λ)/(w₁ + w₂ + α̃), где C — ошибка ограничения; это даёт жёсткость, независимую от числа итераций.

Для геймплея важны: коллизии с капсулой персонажа, ветер как сила на площадь, разрывы по порогу деформации, LOD и «заморозка» ткани, которая не видна. Ткань на сотни частиц дорога; для плащей часто берут скиннинг + кости с физикой, а не полноценную сетку.

математическая модель
Verlet: x′ = 2x − xprev + a·dt², PBD: Δx = ±w/(w₁+w₂)·C, XPBD: α̃ = α/dt²
C — функция ограничения (например, |x₁−x₂| − L). w — обратная масса. α = 0 — жёсткое ограничение.
02 Как это построить
  1. Постройте сетку частиц и ограничений (structural, shear, bend).
  2. Задайте закреплённые точки и начальные позиции; сохраните prev-позиции.
  3. Каждый подшаг: интегрируйте Verlet, затем N итераций проекции ограничений.
  4. Обработайте коллизии (сферы, капсулы, плоскость) после проекций или внутри них.
  5. Добавьте ветер, демпфирование, разрывы и LOD; спите невидимую ткань.

Аэродинамика летательных аппаратов

Aerodynamics and flight models

Подъёмная сила пропорциональна плотности, квадрату скорости и площади крыла, а коэффициент подъёма зависит от угла атаки. Для аркадного полёта достаточно этой формулы, для симулятора — таблиц и срывов потока.

БернуллиCFDаэродинамические коэффициенты
01 Суть

Уравнение подъёмной силы: L = ½·ρ·v²·S·CL(α), сопротивления: D = ½·ρ·v²·S·CD(α). CL растёт линейно с углом атаки до критического (~15°), затем резко падает — это срыв потока (stall), из-за которого самолёт валится. CD = CD0 + CL²/(π·e·AR): индуцированное сопротивление растёт с подъёмной силой.

Принцип Бернулли объясняет часть картины (быстрее поток — ниже давление), но подъём корректнее описывать через отклонение потока и циркуляцию (теорема Жуковского: L = ρ·v·Γ). Для игры важнее эмпирические кривые CL(α), CD(α), чем физическая точность. CFD нужен для дизайна и пре-расчётов, в реальном времени его заменяют таблицами.

Модель полёта: силы в связанной системе координат (тяга, подъём, сопротивление, вес), моменты от элеронов/руля/тангажа, инерция. Устойчивость обеспечивают демпфирующие моменты. Аркада упрощает: самолёт «сам» выравнивается, угол крена управляет поворотом, а срыв отключают. Симулятор требует честной аэродинамики, триммирования и учёта плотности воздуха с высотой.

математическая модель
L = ½ρv²S·CL(α), D = ½ρv²S·(CD0 + CL²/(πeAR))
ρ падает с высотой: ρ ≈ ρ₀·(1 − 2.2557e−5·h)4.2559. Срыв при α > αcrit ≈ 15°.
02 Как это построить
  1. Задайте массу, площадь крыла, размах, кривые CL/CD от угла атаки.
  2. Вычислите скорости в связанной системе, угол атаки и скольжение.
  3. Посчитайте силы и моменты, примените демпфирование по угловым скоростям.
  4. Добавьте тягу, вес, плотность воздуха по высоте и срыв потока.
  5. Настройте управление: для аркады — assist, для симулятора — триммер и честные оси.

Магнитные и гравитационные поля

Vector fields, divergence and curl

Поле задаёт силу в каждой точке пространства. Дивергенция показывает источники, ротор — завихрения; вместе они описывают, можно ли поле представить потенциалом и как визуализировать его без хаоса.

векторные полядивергенция/роторпотенциал
01 Суть

Векторное поле F(x, y) = (P, Q). Дивергенция ∇·F = ∂P/∂x + ∂Q/∂y — плотность источников; ротор (в 2D скаляр) ∇×F = ∂Q/∂x − ∂P/∂y — локальное вращение. Магнитное поле в вакууме безвихревое по источникам (∇·B = 0), электростатическое — потенциальное (∇×E = 0). Гравитация — тоже потенциальное поле с ∇·g = −4πGρ.

В игре поля обычно строят суммой источников: точечный заряд/масса даёт F = k·q·r̂/r², диполь — более сложную картину. Суммировать нужно с ограничением (softening): при r → 0 сила не должна уходить в бесконечность, иначе объекты «выстреливают». Для планет используйте сферически-симметричную модель (внутри — линейный рост силы), а не точечную сингулярность.

Визуализация: линии тока интегрируют dx/ds = F(x)/|F(x)|, цвет — по модулю, стрелки — по направлению. Для геймплея важнее читаемость: не рисуйте поле там, где оно не влияет, ограничьте число линий, используйте анимированные пунктиры. Для магнитных головоломок полезно показать эквипотенциали — они подсказывают, куда покатится объект.

математическая модель
F = k·q·r̂/r², ∇·F = ∂P/∂x + ∂Q/∂y, ∇×F = ∂Q/∂x − ∂P/∂y
Softening: F = k·q·r̂/(r² + ε²). Потенциал φ: F = −∇φ; для точечной массы φ = −GM/r.
02 Как это построить
  1. Определите источники поля и закон силы (1/r², диполь, вихрь).
  2. Добавьте softening и максимальную силу для стабильности.
  3. Считайте силы для динамических объектов; для статичных — пре-бейк поле в текстуру.
  4. Визуализируйте линии тока/эквопотенциали с ограничением плотности.
  5. Проверьте устойчивость интегратора: поле с сильными градиентами требует подшагов.

import math

def field_at(x, y, sources, softening=0.5):
    fx = fy = 0.0
    for sx, sy, strength in sources:
        dx, dy = sx - x, sy - y
        r2 = dx*dx + dy*dy + softening**2
        inv = strength / (r2 * math.sqrt(r2))
        fx += dx * inv
        fy += dy * inv
    return fx, fy

def streamline(x, y, sources, step=2.0, steps=200, bounds=(-200, 200)):
    pts = [(x, y)]
    for _ in range(steps):
        fx, fy = field_at(x, y, sources)
        m = math.hypot(fx, fy) or 1e-9
        x += fx / m * step
        y += fy / m * step
        if not (bounds[0] < x < bounds[1] and bounds[0] < y < bounds[1]):
            break
        pts.append((x, y))
    return pts

Тепловая передача и термодинамика

Heat diffusion and thermodynamics

Тепло течёт от горячего к холодному пропорционально градиенту температуры. Уравнение теплопроводности — это диффузия; в игре его решают на сетке или упрощают до «комнат» с теплоёмкостью.

уравнение Фурьедиффузияэнтропия
01 Суть

Уравнение Фурье: ∂T/∂t = α·∇²T, где α = k/(ρcp) — температуропроводность. На сетке это явная схема: T′ᵢ = Tᵢ + α·dt/h²·(Tᵢ₋₁ − 2Tᵢ + Tᵢ₊₁). Условие устойчивости: α·dt/h² ≤ 0.25 в 2D (≤ 1/6 в 3D). Нарушение даёт осцилляции и «шахматку» — классическая ошибка.

Для геймплея часто достаточно модели «зон»: комнаты с температурой, теплоёмкостью и связями (двери, вентиляция). Тогда теплообмен — это Q = k·(T₁ − T₂), а T′ᵢ = Tᵢ + Q/cᵢ. Это стабильно, дёшево и читаемо: игрок видит, что открытая дверь остужает комнату. Для визуала — тепловая карта и пар/иней как индикаторы.

Термодинамика: первый закон ΔU = Q − W (энергия сохраняется), второй — энтропия не убывает в замкнутой системе. В игре второй закон полезен как дизайн-ограничение: нельзя «вечный двигатель» без отвода тепла. Охлаждение, КПД и перегрев оборудования — это естественная механика для sci-fi и выживания, если показывать числа игроку.

def diffuse(T, alpha, dt, h, iters=1):
    """Явная схема; для устойчивости нужно alpha*dt/h**2 <= 0.25."""
    koef = alpha * dt / (h * h)
    assert koef <= 0.25, "неустойчиво: уменьшите dt или увеличьте h"
    rows, cols = len(T), len(T[0])
    for _ in range(iters):
        new = [row[:] for row in T]
        for y in range(1, rows-1):
            for x in range(1, cols-1):
                lap = (T[y-1][x] + T[y+1][x] + T[y][x-1] + T[y][x+1]
                       - 4*T[y][x])
                new[y][x] = T[y][x] + koef * lap
            # границы: изолированные (нулевой поток) или фиксированные
        T = new
    return T

Бюджет кадра — это задача распределения: у вас 16.6 мс и набор работ с разной стоимостью и зависимостями. Формально это LP/ILP, практически — приоритеты, пулы задач и отсечение по бюджету.

линейное программированиесимплексjob system
01 Суть

Формализация: максимизировать полезность Σ uᵢ·xᵢ при ограничениях Σ cᵢ·xᵢ ≤ B (бюджет), зависимостях (xᵢ ≤ xⱼ) и целочисленности. Симплекс-метод решает непрерывную релаксацию, а округление даёт почти оптимальное расписание. На практике задачи (тени, GI, частицы, физика) дискретны и имеют жёсткие зависимости, поэтому чаще применяют жадный алгоритм по «полезность/стоимость» с отсечением.

Job system: пул задач с зависимостями (DAG), рабочие потоки, lock-free очереди. Ключ — минимизировать синхронизацию и размер задач: слишком мелкие задачи тонут в оверхеде, слишком крупные не дают баланса. Для GPU — command buffers и асинхронные compute-очереди, чтобы не ждать копирования.

Адаптивное качество: измеряйте фактическое время каждой системы, ведите скользящее среднее и решайте, что понизить, если бюджет превышен. Важна гистерезисная политика, чтобы не «мигать» качеством каждый кадр. И отдельный бюджет на CPU и GPU: они перекрываются, но синхронизация может съесть выгоду.

def greedy_schedule(tasks, budget_ms):
    """tasks: [(name, cost_ms, utility, [зависимости])]"""
    done, used, plan = set(), 0.0, []
    remaining = list(tasks)
    while remaining:
        ready = [t for t in remaining if all(d in done for d in t[3])]
        if not ready:
            break
        # максимальная полезность на миллисекунду
        best = max(ready, key=lambda t: t[2] / max(t[1], 1e-6))
        if used + best[1] > budget_ms:
            remaining.remove(best)      # не влезает — исключаем
            continue
        plan.append(best[0]); used += best[1]; done.add(best[0])
        remaining.remove(best)
    return plan, used

Пространственное разбиение для коллизий

Spatial partitioning (BVH, k-d tree, grid)

Проверять все пары объектов — O(n²). Пространственный индекс отбрасывает заведомо далёкие пары и превращает коллизии в почти линейную задачу.

BVHk-d деревоbroadphase
01 Суть

Broadphase: для каждого объекта строится AABB, индекс находит пересекающиеся пары, затем narrowphase проверяет точную геометрию (GJK, SAT, треугольники). Варианты индекса: равномерная сетка (быстро, но плохо при разном масштабе объектов), sweep-and-prune (сортировка по оси, хорош для почти отсортированных данных), BVH (иерархия AABB, лучший выбор для статичной геометрии и raycast), k-d дерево (хорошо для точечных запросов и поиска ближайших).

BVH строят сверху вниз: выбирают ось (SAH — surface area heuristic), сортируют по центроидам, делят пополам. SAH минимизирует ожидаемую стоимость обхода: cost = Ctrav + (SL/S)·CL + (SR/S)·CR. Для динамических объектов BVH перестраивают частично (refit) или используют несколько деревьев по слоям.

Важно: broadphase не заменяет точный тест, а лишь сокращает пары. Для тысяч снарядов быстрее работает сетка с фиксированной ячейкой и «дедупликацией» пар. Для raycast по мешу — BVH с упорядоченным обходом (ближайший ребёнок первым) и ранним выходом. Кэш-локальность решает: массив структур в плоском буфере быстрее дерева указателей.

математическая модель
SAH: cost = Ctrav + (SL/S)·CL + (SR/S)·CR
S — площадь AABB. Для сетки: ячейка ≈ среднему размеру объекта; при разбросе размеров — иерархическая сетка.
02 Как это построить
  1. Соберите AABB всех объектов и выберите структуру под сценарий (сетка, BVH, SAP).
  2. Постройте индекс; для статики — один раз, для динамики — refit/перестройка.
  3. Запрашивайте пары и передавайте их в narrowphase с фильтрами по слоям.
  4. Для raycast обходите дерево с приоритетом ближнего узла и ранним выходом.
  5. Профилируйте: стройка, запросы, обновления — это три разные статьи бюджета.

def union(boxes):
    return (min(b[0] for b in boxes), min(b[1] for b in boxes),
            max(b[2] for b in boxes), max(b[3] for b in boxes))

def overlaps(a, b):
    return not (a[2] < b[0] or b[2] < a[0] or a[3] < b[1] or b[3] < a[1])

class Node:
    __slots__ = ("box", "left", "right", "items")
    def __init__(self, box):
        self.box = box          # (minx, miny, maxx, maxy)
        self.left = self.right = None
        self.items = []

def build(items, leaf_size=4):
    box = union([i[0] for i in items])
    node = Node(box)
    if len(items) <= leaf_size:
        node.items = items
        return node
    # делим по самой длинной оси по медиане центроидов
    axis = 0 if (box[2]-box[0]) >= (box[3]-box[1]) else 1
    items.sort(key=lambda it: (it[0][axis] + it[0][axis+2]) * 0.5)
    mid = len(items) // 2
    node.left, node.right = build(items[:mid], leaf_size), build(items[mid:], leaf_size)
    return node

def query(node, q, out):
    if not overlaps(node.box, q):
        return
    if node.items:
        out.extend(it for it in node.items if overlaps(it[0], q))
    else:
        query(node.left, q, out); query(node.right, q, out)

Сжатие анимационных данных

Animation compression (quantization + curve fitting)

Анимация — это кривые поворотов и позиций, снятые с высокой частотой. Их сжимают квантованием, удалением ключей по допуску и аппроксимацией сплайнами; главное — не потерять стопы и резкие удары.

квантованиесплайныкривые
01 Суть

Кватернион занимает 16 байт; его квантуют в 4×16 бит (8 байт) или в 3×10 бит + восстановление знака (smallest-three). При допуске в 0.1° это визуально незаметно. Позиции и масштаб квантуют по диапазону скелета; для мелких костей (пальцы) диапазон меньше — можно тратить меньше бит.

Ключевой шаг — удаление ключей: кривая аппроксимируется с допуском (например, 0.5 см / 0.5°), лишние ключи убираются, оставшиеся кодируются как сплайн Эрмита с касательными. Алгоритм жадный: наращиваем сегмент, пока ошибка меньше допуска. Это даёт 5–20-кратное сжатие на «плавных» клипах и меньше — на резких.

Продвинутые техники: curve simplification по значимости, кодирование «только изменения» (delta от A-позы), адаптивная частота для разных костей, раздельное сжатие translation/rotation. Для больших клипов — сегментация на куски и потоковая загрузка. Валидация: сравнение визуальных результатов и метрики максимального отклонения, а не среднего — глаз замечает именно пики.

математическая модель
bits ≈ log₂(диапазон/допуск), 3-компонентный кватернион: 32 бита → 30 бит + знак
Ошибка аппроксимации: max|curve(t) − approx(t)| < tolerance на всём интервале.
02 Как это построить
  1. Определите допуски на вращение/позицию в зависимости от размера и видимости кости.
  2. Сконвертируйте кватернионы в компактное представление (smallest-three).
  3. Упростите кривые жадным алгоритмом с контролем максимальной ошибки.
  4. Закодируйте оставшиеся ключи как сплайны с касательными и сожмите поток.
  5. Проверьте визуально и по пиковой ошибке; настройте допуски на резких клипах.

def simplify(keys, tolerance, metric=lambda a, b: abs(a-b)):
    """Жадное удаление ключей: держим точки, пока ошибка линейной
    интерполяции не превышает tolerance."""
    if len(keys) < 3:
        return list(keys)
    out = [keys[0]]
    last = 0
    for i in range(2, len(keys)):
        # проверяем все промежуточные точки против отрезка last -> i
        ok = True
        for j in range(last + 1, i):
            t = (keys[j][0] - keys[last][0]) / (keys[i][0] - keys[last][0])
            approx = keys[last][1] + (keys[i][1] - keys[last][1]) * t
            if metric(keys[j][1], approx) > tolerance:
                ok = False
                break
        if not ok:
            out.append(keys[i-1])
            last = i - 1
    out.append(keys[-1])
    return out

Порталы и неевклидова геометрия

Portals and non-Euclidean geometry

Портал — это преобразование пространства: камера видит сцену через матрицу, которая склеивает два места. Рекурсия порталов, отсечение и корректная физика требуют аккуратной работы с матрицами и ClipPlane.

проективная геометриякватернионыrecursion
01 Суть

Портал задаётся двумя прямоугольниками (вход и выход) с нормалями. Вид через портал — это рендер сцены камерой, преобразованной матрицей: M = Texit · Rexit · Rentry−1 · Tentry−1 (с точностью до масштаба). Текстурная проекция использует ту же матрицу; для рекурсии её применяют повторно, с ограничением глубины.

Геометрически это проективная склейка: пространство, в котором две плоскости отождествлены преобразованием. Кватернионы удобны для ориентации (без gimbal lock), но трансформация портала в общем случае включает отражение/поворот и сдвиг. Отражение (зеркальный портал) меняет ориентацию — это ломает winding triangles, поэтому либо избегают отражений, либо инвертируют culling и нормали.

Проблемы: отсечение геометрии за порталом (oblique near plane / ClipPlane), чтобы не рендерить лишнее и не видеть «сквозь стену»; рекурсия — рендер в текстуру с уменьшением разрешения; физика — телепорт объекта с преобразованием скорости и углового момента; сохранение «камеры» при переносе. Для неевклидовых миров (тор, лента Мёбиуса) нужны порталы-склейки на границах или обёртка координат.

математическая модель
Mportal = Texit·Rexit·Rentry−1·Tentry−1
Скорость после перехода: v′ = R·v, где R — относительный поворот порталов. Для зеркала добавляется отражение нормальной компоненты.
02 Как это построить
  1. Задайте пару порталов с трансформами и нормалями.
  2. Постройте матрицу перехода и матрицу проекции для камеры.
  3. Рендерите вид через портал в текстуру с oblique near plane.
  4. Ограничьте рекурсию по глубине и снижайте разрешение.
  5. При пересечении объектом плоскости переносите его трансформ и скорость.

{

Геймплей на торе и ленте Мёбиуса

Topological gameplay (torus, Möbius)

Тор — это прямоугольник с отождествлёнными краями: вышел справа — вошёл слева. Лента Мёбиуса добавляет переворот при обходе, и это ломает ориентацию, а значит и привычную навигацию.

топологиясклейкиэйлерова характеристика
01 Суть

Тор получается склейкой противоположных сторон квадрата: (x, y) ~ (x + W, y) ~ (x, y + H). Реализация — модульная арифметика координат плюс «призрачные» копии объектов у краёв для рендера и физики. Радиусы и запросы соседей должны учитывать заворот, иначе снаряды пропадают на краю, а ИИ не видит врага «через стену».

Лента Мёбиуса — склейка с переворотом: (0, y) ~ (1, 1 − y). Обход вдоль ленты возвращает объект в ту же точку с перевёрнутой ориентацией; после двух обходов — обратно. Это означает неориентируемость: нельзя глобально определить «верх» и «низ», локальные координаты приходится переносить с матрицей переворота. Для игрока это головоломка, для кода — источник багов с нормалями и камерой.

Топологические инварианты полезны для дизайна: эйлерова характеристика χ = V − E + F (тор: 0, сфера: 2, бутылка Клейна: 0), число «дыр» рода g = (2 − χ)/2. Для геймплея это означает ограничения на разрезы и склейки: нельзя «разрезать» тор в сферу без изменения топологии, и это можно сделать механикой (как в некоторых головоломках).

математическая модель
Тор: (x, y) ~ (x mod W, y mod H), Мёбиус: (0, y) ~ (1, 1 − y)
χ = V − E + F; g = (2 − χ)/2 для замкнутой ориентируемой поверхности. Тор: χ = 0, g = 1.

  2. Реализуйте wrap для позиций, скоростей, запросов и рендера (призрачные копии).
  3. Для Мёбиуса добавьте матрицу переноса ориентации при пересечении шва.
  4. Проверьте камеру, освещение и физику на швах — там ломается ориентация.
  5. Ограничьте сложность: чем больше склеек, тем труднее отлаживать и объяснять игроку.

Система квантовой запутанности

Entanglement as a game mechanic

Запутанность — это корреляция, которую нельзя объяснить локальными скрытыми параметрами. Для игры это механика «парных объектов»: состояние одного мгновенно определяет результат измерения другого, но информацию передать нельзя.

тензорная алгебрагильбертово пространствоБелл
01 Суть

Состояние двух кубитов живёт в тензорном произведении пространств: |ψ⟩ = α|00⟩ + β|01⟩ + γ|10⟩ + δ|11⟩. Запутанное состояние нельзя разложить в произведение |a⟩⊗|b⟩; пример — синглет Белла (|01⟩ − |10⟩)/√2. Матрица плотности ρ = |ψ⟩⟨ψ|, а частичное взятие следа даёт смешанное состояние одного кубита — именно поэтому локально он выглядит случайным.

Ключевой факт: измерение одного кубита в базисе Z даёт 0 или 1 с равной вероятностью, но результат второго идеально коррелирован (для синглета — противоположен). Если измерять под разными углами, корреляция равна −cos θ — это нарушает неравенство Белла (CHSH: |S| ≤ 2, квантово до 2√2). Для геймплея это можно превратить в головоломку: «настрой базис измерения, чтобы получить нужную корреляцию».

Дизайн: запутанные пары как «связанные объекты» — враг и его тень, два замка, дверь и мост. Игрок не может передать сообщение, но может использовать корреляции, зная базис. Обязательно объясняйте правила на языке механики, а не физики, и не давайте «мгновенную связь» — это разрушает и физику, и баланс.

математическая модель
|Φ⁺⟩ = (|00⟩ + |11⟩)/√2, E(a,b) = −cos(a−b), |S| ≤ 2√2
CHSH: S = E(a,b) − E(a,b′) + E(a′,b) + E(a′,b′). Классический предел — 2, квантовый — 2√2 ≈ 2.828.
02 Как это построить
  1. Определите пары запутанных объектов и что именно коррелирует (состояние, урон, позиция).
  2. Задайте базисы измерения, доступные игроку (углы, инструменты).
  3. Реализуйте измерение как вероятностный выбор с корреляцией −cos θ.
  4. Запретите передачу информации: результат второго известен только после измерения первого.
  5. Проверьте баланс: корреляции не должны давать бесплатного обхода уровней.

import math, random

def bell_correlate(a_angle, b_angle, rng=random):
    """Возвращает пару исходов с корреляцией E = -cos(a - b)."""
    p_same = (1.0 - math.cos(a_angle - b_angle)) / 2.0
    a = 0 if rng.random() < 0.5 else 1
    # для синглета: одинаковые исходы при малом угле редки
    b = a if rng.random() < p_same else 1 - a
    return a, b

def chsh(samples=20000, rng=random.Random(1)):
    angles = (0, math.pi/4, math.pi/8, 3*math.pi/8)
    def E(a, b):
        pairs = [bell_correlate(a, b, rng) for _ in range(samples)]
        return sum(1 if x == y else -1 for x, y in pairs) / samples
    return (E(angles[0], angles[2]) - E(angles[0], angles[3])
            + E(angles[1], angles[2]) + E(angles[1], angles[3]))

Динамические системы и хаос

Chaos, bifurcations and attractors

Хаос — это чувствительность к начальным условиям в детерминированной системе. Логистическое отображение и аттрактор Лоренца — канонические модели, а показатель Ляпунова измеряет, насколько быстро решения разбегаются.

теория хаосааттракторыляпуновские показатели
01 Суть

Логистическое отображение: xn+1 = r·xn(1 − xn). При r < 3 — устойчивая точка, при 3 < r < 3.57 — каскад удвоений периода, дальше — хаос с «окнами» порядка. Бифуркационная диаграмма — красивый и понятный инструмент для UI: игрок двигает r и видит, как система меняет поведение.

Аттрактор Лоренца: dx/dt = σ(y − x), dy/dt = x(ρ − z) − y, dz/dt = xy − βz. Траектория не повторяется, но остаётся в ограниченной области (странный аттрактор) и имеет фрактальную размерность. Для визуала достаточно 3D-линий с затуханием; для геймплея — «хаотический» источник движения, который при этом ограничен.

Показатель Ляпунова λ > 0 означает экспоненциальное разбегание: δ(t) ≈ δ₀·eλt. Практический вывод: хаотические системы нельзя предсказывать на длинном горизонте без огромной точности. В мультиплеере это смертельно для детерминизма; в одиночной игре — источник неповторяемости. Используйте хаос осознанно: для фоновых эффектов, а не для критичной симуляции.

математическая модель
xn+1 = r·xn(1 − xn), λ = lim (1/n)·Σ ln|f′(xᵢ)|
Лоренц: σ = 10, ρ = 28, β = 8/3. λ > 0 — хаос; для Лоренца λ ≈ 0.9.

  1. Выберите отображение/систему и параметр, который будет менять игрок.
  2. Постройте бифуркационную диаграмму или фазовый портрет для настройки.
  3. Оцените показатель Ляпунова и горизонт предсказуемости.
  4. Визуализируйте траектории с затуханием и цветом по времени.
  5. Не используйте хаос для критичной физики в сети; для эффектов — ограничьте амплитуду.

def logistic(r, x0=0.5, n=1000, skip=100):

def lyapunov(r, x0=0.5, n=2000, skip=200):
    x, total = x0, 0.0
    for i in range(n + skip):
        x = r * x * (1 - x)
        if i >= skip:
            d = abs(r * (1 - 2 * x))
            total += math.log(d) if d > 1e-12 else -30
    return total / n          # > 0 — хаос

def lorenz_step(p, dt=0.01, sigma=10, rho=28, beta=8/3):
    x, y, z = p
    dx = sigma * (y - x)
    dy = x * (rho - z) - y
    dz = x * y - beta * z
    return (x + dx*dt, y + dy*dt, z + dz*dt)

Анализ игрового баланса оружия

Weapon balance analysis (regression, ANOVA)

Баланс оружия проверяют не «на глаз», а метриками: время до убийства, DPS с учётом промахов, винрейт и пикрейт. Регрессия показывает, какие характеристики реально предсказывают силу.

регрессияANOVATTK
01 Суть

Теоретическая сила оружия: TTK = HP/(урон·скорострельность) с поправкой на перезарядку и промахи. Эффективный DPS = урон·RPM/60·accuracy/(1 + reload_time/engagement_time). Но главная метрика — не цифра в таблице, а результат: winrate оружия при контроле скилла игрока (например, в разрезе рейтинга).

Регрессия: winrate ~ β₀ + β₁·dps + β₂·accuracy + β₃·range + ε. Коэффициенты говорят, какой параметр «перевешивает». ANOVA сравнивает группы (оружие/класс) и проверяет, значимы ли различия вообще, или это шум выборки. Обязательно считайте доверительные интервалы: при 500 матчах разница в 2 % винрейта может быть неотличима от случайности.

Пикрейт — важнейшая метрика: если оружие берут в 60 % матчей и оно выигрывает 52 %, оно доминирует. Обратная связь: нерфьте не «цифру урона», а то, что делает оружие безальтернативным (универсальность, отсутствие контр-пиков). И тестируйте изменения на симуляциях/ботах до выката, иначе правки баланса превращаются в лотерею.

математическая модель
TTK = HP / (DPS·accuracy), DPS = урон·RPM/60 / (1 + reload/engagement)
Регрессия: y = Xβ + ε; ANOVA: F = MSмежду/MSвнутри, p < 0.05 — различия значимы.

  3. Постройте регрессию и проверьте значимость коэффициентов.

Система matchmaking для ранговых игр

Matchmaking with Elo, Glicko-2 and TrueSkill

Матчмейкинг решает две задачи: оценить силу игрока и собрать матч с равными шансами. Elo — простой, но нестабильный; Glicko-2 и TrueSkill учитывают неопределённость и командную игру.

EloGlicko-2TrueSkillбайес
01 Суть

Elo: ожидаемый результат E = 1/(1 + 10(Ropp−R)/400), обновление R′ = R + K(S − E). Проблемы: K фиксирован, неопределённость не моделируется, новичок и ветеран с одинаковым рейтингом считаются равными. Тем не менее Elo отлично работает как «валюта» рейтинга и понятен игрокам.

Glicko-2 добавляет rating deviation (RD) и volatility: после долгого перерыва RD растёт, и рейтинг быстрее меняется — система «перепроверяет» игрока. TrueSkill — байесовская модель для команд: сила игрока — гауссиана N(μ, σ²), обновление по теореме Байеса, а матчмейкинг минимизирует ожидаемую «нечестность» матча (draw probability).

Практика: матчмейкер оптимизирует не только равенство силы, но и время ожидания, регион, размер группы, очередность ролей. Часто используют расширяющийся диапазон поиска и «качество» матча как функцию от дисперсии рейтингов. Смурфы и бустинг — отдельная проблема: нужны быстрые калибровочные матчи и детекция аномалий прогресса.

математическая модель
E = 1/(1 + 10(Rb−Ra)/400), R′ = R + K(S − E)
TrueSkill: качество матча = 2·Φ(μdiff/√(2β² + σa² + σb²)), где β — «масштаб удачи».

Прогнозирование игровых трендов

Time-series forecasting (ARIMA, seasonality)

Тренды игроков и продаж — временные ряды с трендом, сезонностью и шумом. ARIMA моделирует автокорреляцию, а сезонность ловит недельные и событийные всплески.

ARIMAсезонностьаномалии
01 Суть

Стационарность — ключевое условие. Ряд с трендом дифференцируют: Δyₜ = yₜ − yₜ₋₁. AR(p) описывает зависимость от прошлых значений, MA(q) — от прошлых ошибок; ARIMA(p,d,q) объединяет их. Сезонность добавляют сезонной разностью: SARIMA(p,d,q)(P,D,Q)s с s = 7 (дни недели) или 24 (часы).

Для игровых метрик полезны: DAU/MAU, retention D1/D7/D30, конверсия, ARPPU, длина сессии. Пики от ивентов и обновлений ломают модель — их нужно выносить в отдельные регрессоры или помечать как аномалии, иначе прогноз «размазывается». Логарифмирование стабилизирует дисперсию мультипликативных рядов.

Валидация — только по времени, не случайным разбиением: обучаем на прошлом, проверяем на будущем. Метрики: MAE, RMSE, MAPE и, главное, бизнес-ценность (ошибка в прогнозе нагрузки стоит дороже ошибки в прогнозе контента). Простые бейзлайны (naive, seasonal-naive) часто обыгрывают сложные модели — всегда сравнивайте.

математическая модель
ARIMA(p,d,q): (1 − ΣφᵢLⁱ)(1−L)dyₜ = (1 + ΣθⱼLʲ)εₜ
L — лаг-оператор. SARIMA добавляет сезонные полиномы с периодом s. MAPE = (100/n)·Σ|y − ŷ|/|y|.
02 Как это построить
  1. Постройте ряд и проверьте стационарность (дифференцирование, тест ADF).
  2. Определите p, q по ACF/PACF или информационным критериям (AIC).
  3. Добавьте сезонность и регрессоры для ивентов/обновлений.
  4. Валидируйте по времени и сравнивайте с бейзлайнами.
  5. Отслеживайте дрейф модели и переобучайте по расписанию.

Вероятностные системы лута

Loot systems (Pareto, CLT, pity)

Лут — это распределение наград с длинным хвостом. Парето описывает «богатые становятся богаче», ЦПТ — суммарный лут за серию, а pity-механика ограничивает худший случай.

распределение ПаретоЦПТpity
01 Суть

Распределение Парето: P(X > x) = (xm/x)α. Малые α дают тяжёлый хвост: большинство наград дешёвые, редкие — очень дорогие. Для лута это естественная модель: 90 % дропа — мусор, 1 % — легендарки. Но чистый Парето может выдать «джекпот» на старте и сломать прогрессию, поэтому хвост обрезают и добавляют гарантии.

Центральная предельная теорема: сумма независимых одинаково распределённых величин стремится к нормальному распределению. Значит, суммарный лут за N открытий предсказуем (среднее N·μ и дисперсия N·σ²) даже если отдельные дропы — Парето (при конечной дисперсии). Это позволяет проектировать «бюджет наград» на сессию и проверять, не выходит ли игрок за кривую прогрессии.

Pity и гарантии: «не более N попыток до редкого», «первые 10 открытий с повышенным шансом», «дубликаты конвертируются в валюту». Это уменьшает дисперсию восприятия, но меняет математику: эффективная вероятность становится условной, и её надо считать честно. Юридически во многих странах раскрытие шансов обязательно — проектируйте систему так, чтобы её можно было объяснить игроку.

математическая модель
P(X > x) = (xm/x)α, Σi=1..NXᵢ ≈ N(N·μ, N·σ²)
Pity: P(успех на k-й) = p, если k < N; 1, если k = N. Ожидаемое число попыток = (1 − (1−p)N)/p.
02 Как это построить
  1. Задайте редкости, базовые шансы и веса предметов внутри редкости.
  2. Смоделируйте распределение стоимости лута (Парето/логнормальное).
  3. Добавьте pity и гарантии, пересчитайте эффективные шансы.
  4. Проверьте бюджет: сколько наград игрок получает за час/сессию.
  5. Опубликуйте шансы и добавьте защиту от «сухого» лута.

Определение видимости в 3D-пространстве

Visibility: PVS, portals, BSP

Видимость — это отсечение того, что не попадает в кадр или закрыто. BSP делит пространство плоскостями, порталы отсекают по комнатам, PVS заранее хранит «что видно из этой зоны».

BSPPVSocclusion culling
01 Суть

BSP-дерево рекурсивно делит пространство плоскостями (обычно по граням геометрии). Это даёт корректный порядок отрисовки спереди назад и позволяет быстро отсекать целые поддеревья. В Quake BSP был основой рендера и коллизий. Минус — статичность: любое изменение геометрии требует перестройки.

PVS (potentially visible set): пространство делят на листья, для каждого листа заранее вычисляют список видимых листьев. В рантайме рисуем только их. Это классическая техника BSP-игр и современных движков (precomputed visibility). Порталы — другой подход: комнаты соединены порталами, и если цепочка порталов не попадает в фрустум, комната целиком отсекается.

Современный стек: frustum culling (по AABB), occlusion culling (иерархический Z-buffer, hardware occlusion queries), LOD и HLOD. Важно: отсечение по камере не заменяет отсечение по свету — для теней нужен свой набор кастеров. Для открытых миров статический PVS почти бесполезен, работают GPU-driven culling и кластеры.

математическая модель
Плоскость: n·x + d = 0, фрустум: 6 полупространств
Точка видима, если для всех плоскостей n·x + d ≥ 0. Для AABB тест по положительной/отрицательной вершине.

  4. Настройте LOD/HLOD и бюджет draw calls.

Расчёт траекторий рикошетов

Ricochet and reflection vectors

Идеальный рикошет — отражение скорости относительно нормали: v′ = v − 2(v·n)n. Реалистичный — с потерей энергии, разбросом и условием «не срикошетило», зависящим от угла и материала.

отражениезакон Снелласлучайность
01 Суть

Формула отражения работает для идеально упругого удара. В жизни энергия теряется: v′ = e·(v − 2(v·n)n), где e — коэффициент восстановления (0.3–0.9). Для пуль добавляют потерю скорости и отклонение от нормали, зависящее от шероховатости поверхности. При малом угле падения (почти касательно) пуля чаще рикошетирует, при большом — деформируется и застревает.

Критерий рикошета: угол между скоростью и нормалью. Если |v·n|/|v| < cos(θcrit), то рикошет; иначе — попадание. θcrit зависит от материала и скорости: для стали ~5–15°, для бетона ~10–20°, для брони — больше. Это дешёвая и правдоподобная модель для шутеров.

После отражения луч продолжает жить: нужен лимит отскоков, трассировка следующего сегмента и затухание. Для визуала — трассер по каждому сегменту с временным затуханием. Для геймплея — предсказание рикошета (рикошет от стены в цель) как отдельная механика; тогда критерий и разброс должны быть детерминированными, иначе игрок не сможет учиться.

математическая модель
v′ = v − 2(v·n)·n, с потерей: v′ = e·(v − 2(v·n)·n)
Условие рикошета: |v·n|/|v| < cos θcrit. Для преломления (Снелл): n₁sinθ₁ = n₂sinθ₂.
02 Как это построить
  1. Трассируйте луч, найдите нормаль поверхности и материал.
  2. Проверьте критерий рикошета по углу и типу поверхности.
  3. Отразите скорость, уменьшите модуль на коэффициент восстановления.
  4. Добавьте малый случайный разброс и трассер/эффект.
  5. Повторяйте до лимита отскоков или потери энергии.

Генерация воксельных миров

Voxel worlds and marching cubes

Воксельный мир — это сетка значений плотности. Поверхность извлекают marching cubes (полигональная сетка) или рендерят напрямую ray marching; хранение — octree или плоские чанки.

marching cubesSDFоктодерево
01 Суть

Marching cubes: кубическая ячейка 2×2×2 сэмпла, 256 комбинаций знаков — таблица рёбер и треугольников. Вершины интерполируются по плотности, что даёт сглаженную поверхность. Алгоритм простой и хорошо параллелится, но генерирует много треугольников и имеет проблемы с тонкими деталями (диагональная связность решается marching tetrahedra).

SDF (signed distance field) удобнее для редактирования: f(x) < 0 внутри, > 0 снаружи. Сложение — min(f₁, f₂), вычитание — max(f₁, −f₂), сглаженное объединение — smooth min. CSG-редактирование мира становится композицией функций, а не перестройкой сетки. Для рендера — ray marching по SDF, для физики — сетка из marching cubes или приближение.

Хранение: чанки 32³ в плоских массивах с октодревом для LOD, палитра блоков вместо полного описания, меш-кэш и отложенная перестройка только изменённых чанков. Для больших миров критичны: генерация в фоне, стриминг, сжатие (RLE) и ограничение числа треугольников на кадр. Меш-генерация на 32³ чанке занимает единицы миллисекунд — этого достаточно для интерактивного редактирования.

математическая модель
SDF: f(x) < 0 внутри, f(x) = 0 на поверхности; union = min(f₁, f₂)
Интерполяция вершины: p = p₁ + (0 − f₁)/(f₂ − f₁)·(p₂ − p₁). Октодерево даёт LOD с шагом 2l.

  2. Постройте функцию плотности/палитру и разбейте мир на чанки.

Процедурные текстуры материалов

Procedural textures (noise, FFT, weathering)

Процедурная текстура — это функция координат, а не картинка. Шум, ячейки Вороного и свёртки дают дерево, металл, камень; цена — вычисления в шейдере и борьба с тайлингом.

шумпреобразования Фурьеtiling
01 Суть

Базовые кирпичи: value/Perlin/simplex-шум, ячейки Вороного (F1/F2 — расстояние до ближайших точек), градиенты и волны. Композиция — это смешивание по маскам: камень = fBm + Voronoi cracks, дерево = годичные кольца по расстоянию + шум волокон, металл = почти однородный albedo + шероховатость по шуму.

Тайлинг: периодический шум (сэмплирование по модулю периода) даёт бесшовность. Продвинутый вариант — «tileable» генерация через FFT: генерируем спектр, фильтруем и делаем обратное преобразование — результат периодичен по построению. Для устранения видимых повторов используют domain warping, несколько масштабов и стохастический тайлинг (texture bombing).

PBR: albedo, normal, roughness, metallic. Процедурно генерировать normal можно из карты высот (Sobel), roughness — из шума и карты загрязнений, а AO — из высоты или SDF. Вычислительная цена в шейдере: 3D-шум на пиксель дорог, поэтому текстуры часто пекут в атласы офлайн, а в рантайме смешивают слои по маскам.

Normal из высоты: n = normalize(−∂h/∂x, −∂h/∂y, 1). Периодический шум: noise(x mod P, y mod P).

Эффекты искажения пространства

Screen-space distortion with complex numbers

Искажение экрана — это отображение UV. Комплексные функции дают красивые конформные эффекты (сохраняют углы), а шум и поля — динамику. Главное — не ломать читаемость интерфейса.

комплексные числаконформные отображенияUV
01 Суть

Комплексная плоскость: z = u + iv, отображение w = f(z). Конформные функции (w = z², w = ez, w = 1/z) сохраняют углы локально — именно поэтому выглядят «правильно», как линзы и водовороты. Инверсия 1/z даёт «чёрную дыру», экспонента — закручивание, степень zn — n-лучевые искажения.

Практика: сэмплируем сцену не в UV, а в f(UV + смещение). Нужно ограничивать область влияния (маска радиуса), чтобы не искажать весь экран, и защищать UI — интерфейс рендерится после distortion или имеет отдельный слой. Для анимации используем время как параметр и шум как фазовое смещение.

Побочные эффекты: размытие по краям (сэмплирование за пределами [0,1] даёт артефакты — clamp или border), хроматическая аберрация (смещение каналов), виньетка. Для «магии» и порталов важно добавлять яркость/цвет в центре, иначе эффект выглядит как баг. И обязательно настройка «выключить искажения» в опциях доступности.

математическая модель
w = f(z), z = u + iv, lens: w = z + k·zm, swirl: w = z·ei·θ(r)
θ(r) = a·e−r²/σ². Инверсия: w = c/z даёт «чёрную дыру» с радиальным растяжением.
02 Как это построить
  1. Определите центр, радиус и силу искажения; постройте маску.
  2. Выберите функцию (линза, вихрь, инверсия) и параметры анимации.
  3. Смещайте UV с ограничением и защитой от выхода за границы.
  4. Добавьте хроматическую аберрацию и свечение для читаемости.
  5. Отрендерите UI после эффекта и дайте опцию отключения.

// линза: радиальное смещение UV
vec2 lens(vec2 uv, vec2 center, float radius, float strength) {
    vec2 d = uv - center;
    float r = length(d);
    float m = 1.0 - smoothstep(radius * 0.6, radius, r);
    float k = strength * m * m;
    return uv - d * k * (r / radius);
}

// вихрь на комплексной плоскости: w = z * exp(i * theta(r))
vec2 swirl(vec2 uv, vec2 center, float strength, float time) {
    vec2 d = uv - center;
    float r = length(d);
    float a = strength * exp(-r * r * 8.0) + time;
    float s = sin(a), c = cos(a);
    vec2 rot = vec2(d.x * c - d.y * s, d.x * s + d.y * c);
    return center + rot;
}

vec4 distort(sampler2D scene, vec2 uv, vec2 center) {
    vec2 warped = swirl(lens(uv, center, 0.35, 0.25), center, 2.0, 0.0);
    // хроматическая аберрация
    float r = texture(scene, warped + vec2(0.002, 0.0)).r;
    float g = texture(scene, warped).g;
    float b = texture(scene, warped - vec2(0.002, 0.0)).b;
    return vec4(r, g, b, 1.0);
}

Симуляция оптических явлений

Optics: diffraction, BRDF, dispersion

Оптика в игре — это модели отражения и преломления. BRDF описывает, сколько света уходит в направлении камеры, а дифракция и дисперсия добавляют радугу и ореолы вокруг источников.

ФренельBRDFдифракция
01 Суть

BRDF Microfacet (Cook–Torrance): f = D·G·F/(4·(n·l)(n·v)), где D — распределение микронормалей (GGX), G — затенение, F — Френель (Schlick: F = F₀ + (1−F₀)(1−cosθ)⁵). Энергосбережение требует, чтобы f удовлетворяла ∫ f·cosθ dω ≤ 1; иначе материал «светится».

Преломление по закону Снелла: n₁sinθ₁ = n₂sinθ₂. Дисперсия — зависимость n от длины волны: рендерим три канала с разными показателями (или больше для спектрального рендера). Это даёт радужные каустики и призматические эффекты. Полное спектральное решение дорого, но три канала обычно достаточно.

Дифракция и глоу: интеграл Френеля описывает дифракцию на краях, но в играх её заменяют bloom (свёртка с ядром), lens flare и artist-driven ореолы. Волновая оптика нужна только для научных визуализаций. Для фотореализма важнее правильная экспозиция, тонмаппинг и цветовая температура — они дают больше, чем точная дифракция.

математическая модель
f = D·G·F / (4·(n·l)(n·v)), F = F₀ + (1−F₀)(1−cosθ)⁵, n₁sinθ₁ = n₂sinθ₂
GGX: D = α²/(π·((n·h)²(α²−1)+1)²). Дисперсия: n(λ) — разные показатели для R/G/B.
02 Как это построить
  1. Выберите модель BRDF под материалы: GGX + Schlick для металлов/диэлектриков.
  2. Настройте F₀ (0.04 для диэлектриков, albedo для металлов).
  3. Добавьте преломление с дисперсией для стекла/воды, если нужно.
  4. Сделайте bloom/flare и тонмаппинг для читаемости источников.
  5. Проверьте энергосбережение и отсутствие «светящихся» материалов в тени.

float distributionGGX(vec3 N, vec3 H, float roughness) {
    float a = roughness * roughness;
    float a2 = a * a;
    float NdotH = max(dot(N, H), 0.0);
    float denom = NdotH * NdotH * (a2 - 1.0) + 1.0;
    return a2 / (3.14159 * denom * denom);

float geometrySmith(float NdotV, float NdotL, float roughness) {
    float k = (roughness + 1.0) * (roughness + 1.0) / 8.0;
    float gv = NdotV / (NdotV * (1.0 - k) + k);
    float gl = NdotL / (NdotL * (1.0 - k) + k);
    return gv * gl;
}

vec3 specularBRDF(vec3 N, vec3 V, vec3 L, vec3 F0, float roughness) {
    vec3 H = normalize(V + L);
    float NdotV = max(dot(N, V), 1e-4);
    float NdotL = max(dot(N, L), 0.0);
    float D = distributionGGX(N, H, roughness);
    float G = geometrySmith(NdotV, NdotL, roughness);

}

Динамическая балансировка рынка

Auction design and market clearing

Аукцион — это правило распределения и цены. Аукцион второй цены (Викри) стимулирует говорить правду, а двойной аукцион сходится к равновесию спроса и предложения.

аукцион Викриравновесиерынок
01 Суть

Аукцион Викри (second-price sealed-bid): побеждает максимальная ставка, но платит второй максимум. Доминирующая стратегия — ставить свою истинную ценность: завышение не увеличивает выигрыш, занижение рискует проиграть. Для игрового рынка это лучший вариант, если нужно честное распределение редких предметов без «снайпинга» в последнюю секунду.

Двойной аукцион: покупатели и продавцы подают заявки, сделки совершаются при пересечении цен. Равновесная цена — точка, где кривые спроса и предложения пересекаются. В играх это реализуется как книги заявок (order book) с матчингом по цене-времени. Тонкость — минимальный шаг цены, комиссия и защита от манипуляций (wash trading, спам заявок).

Аукцион первой цены с закрытыми ставками теоретически эквивалентен по ожидаемому доходу (теорема эквивалентности доходов), но стратегически сложнее: нужно «сбривать» ставку. Для игроков это непрозрачно, поэтому в геймдизайне чаще выбирают Викри или английский аукцион. Прозрачность правил важнее математической элегантности.

математическая модель
Викри: победитель = argmax bᵢ, платит maxj≠i bⱼ. Двойной аукцион: сделка при bbuy ≥ asell
Ожидаемый доход в аукционе первой цены с n участниками и равномерными ценностями: (n−1)/n · vmax.
02 Как это построить
  1. Выберите формат: Викри, английский, двойной аукцион или мгновенная покупка.
  2. Определите шаг цены, комиссию и антиснайпинг (продление при ставке в конце).
  3. Реализуйте книгу заявок с матчингом по цене-времени.
  4. Добавьте защиту от манипуляций и лимиты на одного игрока.
  5. Логируйте сделки и стройте индексы цен для мониторинга инфляции.

import heapq

def vickrey(bids):
    """bids: [(player, value)] → (победитель, цена)."""
    ordered = sorted(bids, key=lambda b: b[1], reverse=True)
    winner = ordered[0][0]
    price = ordered[1][1] if len(ordered) > 1 else 0.0
    return winner, price

class OrderBook:
    def __init__(self):
        self.bids, self.asks = [], []      # max-heap / min-heap

    def add_bid(self, price, qty, owner):
        heapq.heappush(self.bids, (-price, owner, qty))

    def add_ask(self, price, qty, owner):
        heapq.heappush(self.asks, (price, owner, qty))

    def match(self):
        trades = []
        while self.bids and self.asks and -self.bids[0][0] >= self.asks[0][0]:
            bp, buyer, bq = heapq.heappop(self.bids)
            ap, seller, aq = heapq.heappop(self.asks)
            qty = min(bq, aq)
            trades.append((buyer, seller, -bp, ap, qty))
            if bq > qty: heapq.heappush(self.bids, (bp, buyer, bq - qty))
            if aq > qty: heapq.heappush(self.asks, (ap, seller, aq - qty))
        return trades

Алгоритмы распределения ресурсов

Resource allocation and optimal control

Распределение ресурсов — это оптимизация: максимизировать ценность при ограничениях. Линейное программирование даёт точное решение, а приоритеты и «жадность» — быстрый и понятный игроку вариант.

оптимальное управлениеLPприоритеты
01 Суть

Классическая задача: у базы есть N ресурсов, M юнитов и K зданий; нужно распределить рабочих так, чтобы максимизировать производство или время до цели. Формально это LP: max Σ vᵢxᵢ при ограничениях на ресурсы и здания. Симплекс-метод решает за полиномиальное время; для маленьких задач хватает перебора и жадности.

Оптимальное управление добавляет время: u(t) — управление, x′(t) = f(x, u) — динамика, J = ∫ L(x, u)dt — функционал. Для игр это обычно слишком абстрактно; на практике используют MPC (model predictive control): на каждом шаге решают задачу на горизонте H и применяют только первое управление. Это устойчиво к изменениям и понятно дизайнеру.

Геймплейно важнее прозрачность: игрок должен понимать, почему рабочий пошёл в шахту, а не в лес. Приоритеты (голод > производство > стройка), резервы и «мягкие» ограничения читаются лучше, чем скрытый оптимизатор. Идеальный вариант — LP для «советника ИИ», а не для автоматического управления; игрок принимает решения, система подсказывает.

математическая модель

def greedy_allocate(workers, jobs, priority):
    """jobs: [(name, need_workers, value)] → распределение."""

    return plan, left

Моделирование инфляционных процессов

In-game inflation and monetary sinks

Инфляция в игре — это рост денежной массы без роста товаров. Уравнение обмена MV = PQ связывает деньги, скорость, цены и объём; лечится стоками (налоги, ремонт, расходники), а не только нерфом дропа.

монетарная экономикастокиуравнение обмена
01 Суть

Уравнение обмена: M·V = P·Q. Если денег M становится больше при том же объёме Q и скорости V, цены P растут. В игре M растёт от дропа/квестов, V — от того, как часто игроки тратят, Q — от производства. Инфляция ощущается как «всё дорого, а заработать легко»; дефляция — как «нечего покупать, деньги копятся».

Стоки (sinks): налоги, комиссии аукциона, ремонт, расходники, крафт с шансом провала, аренда, «сжигание» валюты в косметике. Важно, чтобы сток был пропорционален богатству: фиксированная цена ремонта не остановит миллионера. Прогрессивный налог на богатство и комиссия с оборота работают лучше.

Мониторинг: индекс цен (корзина типичных товаров), M2 (общая валюта в экономике), доля валюты у топ-1 % игроков, скорость оборота. Если индекс растёт быстрее дохода новых игроков — экономика «закрывается» для новичков. Регулируйте мягко: событие-сток, сезонный сбор, новые товары, а не резкий нерф, который обесценивает труд игроков.

математическая модель
M·V = P·Q, π ≈ ΔM/M + ΔV/V − ΔQ/Q
π — темп инфляции. Если ΔM = 10 %, ΔV = 0, ΔQ = 4 %, то π ≈ 6 %.
02 Как это построить
  1. Определите M (все источники валюты) и Q (объём товаров и услуг).
  2. Введите стоки, пропорциональные богатству, а не фиксированные.
  3. Постройте индекс цен по корзине и отслеживайте его.
  4. Добавьте сезонные стоки и новые товары как мягкие регуляторы.
  5. Следите за разрывом между новичками и ветеранами; выравнивайте доходность.

Пространственный 3D-звук

Spatial audio and HRTF

3D-звук строится на двух подсказках: разнице времени прихода (ITD) и разнице громкости (ILD). HRTF добавляет форму ушной раковины, а сферические гармоники позволяют эффективно кодировать поле.

HRTFITD/ILDсферические гармоники
01 Суть

ITD (interaural time difference) — до 0.7 мс между ушами; ILD (level difference) — до 20 дБ на высоких частотах, где голова затеняет звук. Мозг объединяет их с спектральными подсказками от ушной раковины, чтобы определить не только азимут, но и elevation. Без HRTF звук «слева/справа» слышен, а «сверху/снизу» — почти нет.

HRTF — это передаточная функция от источника к барабанной перепонке: y(t) = h(t) * x(t), где h зависит от направления. Измеряют на манекенах (KEMAR) или симулируют. Свёртка с HRTF на каждый источник дорога; на практике используют набор из 16–32 направлений с интерполяцией или Ambisonics-панорамирование.

Ambisonics первого порядка (4 канала: W, X, Y, Z) кодирует поле сферическими гармониками; декодирование в наушники/колонки даёт вращающуюся сцену. Для VR это стандарт: звук привязан к миру и поворачивается с головой. Reverb-зоны, окклюзия (звук за стеной глуше) и общая громкость по расстоянию (1/r) завершают картину.

математическая модель
ILD ≈ 20·log₁₀(rfar/rnear), y = h(θ,φ) * x
Ambisonics: B-format W = p/√2, X = p·cosθcosφ, Y = p·sinθcosφ, Z = p·sinφ.
02 Как это построить
  1. Выберите рендерер: стерео-панорама, Ambisonics или HRTF-свёртка.
  2. Реализуйте затухание по расстоянию и воздушное поглощение высоких частот.
  3. Добавьте окклюзию/обструкцию через raycast и фильтр низких частот.
  4. Настройте reverb-зоны и приоритеты голосов (voice limiting).
  5. Проверьте на наушниках и колонках; дайте опции для слабослышащих.

HEAD_WIDTH = 0.18

def itd_ild(azimuth_deg, distance=2.0):
    """Простая модель: задержка и разница уровня между ушами."""
    theta = math.radians(azimuth_deg)
    path_diff = HEAD_WIDTH * math.sin(theta)
    itd = path_diff / SPEED_OF_SOUND          # секунды
    ild_db = 20.0 * math.log10(max(1e-3, (distance - path_diff/2) /
                                        (distance + path_diff/2)))
    return itd, ild_db

def distance_gain(distance, ref=1.0, rolloff=1.0):
    return ref / (ref + rolloff * max(0.0, distance - ref))

def air_absorption(freq_hz, distance_m):
    # упрощённо: высокие частоты гаснут быстрее
    return math.exp(-distance_m * (0.001 + freq_hz * 2e-6))

Физическое моделирование инструментов

Physical modeling synthesis (Karplus–Strong, waveguide)

Струна — это линия задержки с фильтром в обратной связи. Модель Karplus–Strong даёт гитару за 6 строк кода, а цифровые волноводы — духовые и смычковые с резонансами.

волноводКИХ-фильтрырезонанс
01 Суть

Karplus–Strong: заполняем кольцевой буфер шумом (возбуждение), затем на каждом шаге y[n] = 0.5·(y[n−N] + y[n−N−1])·decay. Это простейший волновод: задержка N = sample_rate/frequency, усреднение — фильтр низких частот, decay — потери. Звук поразительно похож на щипковую струну.

Цифровой волновод (waveguide): линия задержки с фильтром потерь и нелинейностью на конце. Для духовых — нелинейность (клапан) и резонатор; для смычковых — трение (модель струны-смычка). Расширение: несколько параллельных волноводов для корпуса, резонансные фильтры для дерева/металла.

Плюсы перед сэмплами: бесконечная вариативность, малый размер, реакция на параметры в реальном времени (сила щипка, позиция, длина). Минусы: сложно настроить тембр, дорого при сотнях голосов, артефакты при экстремальных параметрах. Для игр часто гибрид: сэмплы для основных нот, физическое моделирование для вариаций.

математическая модель
y[n] = 0.5·(y[n−N] + y[n−N−1])·d, N = fs/f₀
Волновод: y[n] = x[n] + g·H(y[n−N]), где H — фильтр потерь, g — усиление обратной связи (стабильно при |g·H| < 1).
02 Как это построить
  1. Задайте частоту, длину струны и коэффициент потерь.
  2. Реализуйте линию задержки с интерполяцией для точной частоты.
  3. Добавьте возбуждение (шум/импульс) и нелинейность для щипка/удара.
  4. Настройте резонансы корпуса и стерео-размещение.
  5. Ограничьте число голосов и добавьте anti-aliasing/сглаживание параметров.

import random

def karplus_strong(freq, duration, sample_rate=44100, decay=0.996):
    n = int(sample_rate / freq)
    buffer = [random.uniform(-1, 1) for _ in range(n)]
    out, idx = [], 0
    prev = 0.0
    for _ in range(int(duration * sample_rate)):
        cur = buffer[idx]
        out.append(cur)
        # низкочастотный фильтр + потери
        new = 0.5 * (cur + prev) * decay
        buffer[idx] = new
        prev = cur
        idx = (idx + 1) % n
    return out

# 220 Гц, 2 секунды — узнаваемая щипковая струна
samples = karplus_strong(220.0, 2.0)

Генерация контента через GAN

GANs for game content

GAN — это соревнование генератора и дискриминатора. Генератор создаёт контент, дискриминатор отличает его от настоящего; обучение двигает оба к равновесию, где подделка неотличима.

GANВассерштейнbackprop
01 Суть

Минимакс: minG maxD E[log D(x)] + E[log(1 − D(G(z)))]. На практике это нестабильно: дискриминатор слишком сильный → градиенты генератора исчезают. Wasserstein GAN заменяет логарифмы на расстояние Вассерштейна (землекопное расстояние) и требует 1-липшицевости D (weight clipping или gradient penalty). Обучение становится стабильнее и метрика осмысленнее.

В играх GAN применяют для: текстурирования (pixel-art тайлы, материалы), генерации уровней (сырые карты → проходимые через пост-обработку), портретов NPC, аугментации данных. Ключевая проблема — контроль: обычный GAN не гарантирует, что сгенерированный уровень проходим или персонаж не имеет шести пальцев. Поэтому добавляют conditioning (cGAN), пост-валидацию правилами и отбраковку.

Альтернативы и гибриды: диффузионные модели дают лучшее качество и контроль, но дороже в инференсе; VAE — быстрее, но размытее; для тайлов часто достаточно процедурных правил + GAN для стилизации. Метрики: FID (сходство распределений), визуальная экспертиза и, главное, доля прошедших игровых валидаций.

математическая модель
minGmaxD Ex[log D(x)] + Ez[log(1 − D(G(z)))]
WGAN: max‖f‖L≤1 E[f(x)] − E[f(G(z))]. Gradient penalty: λ·(‖∇x̂f(x̂)‖₂ − 1)².
02 Как это построить

  2. Соберите датасет и обучите baseline (DCGAN/WGAN-GP).
  3. Добавьте conditioning (класс, стиль, параметры уровня).
  4. Постройте пост-валидацию правилами и отбраковку.
  5. Оценивайте FID и долю валидных образцов; не гонитесь за FID в ущерб играбельности.

def gradient_penalty(D, real, fake, lambda_=10.0):
    alpha = torch.rand(real.size(0), 1, 1, 1)
    mixed = (alpha * real + (1 - alpha) * fake).requires_grad_(True)
    grad = torch.autograd.grad(D(mixed).sum(), mixed, create_graph=True)[0]
    return lambda_ * ((grad.flatten(1).norm(2, dim=1) - 1) ** 2).mean()

Апскейлинг графики в реальном времени

Real-time upscaling (DLSS/FSR/XeSS)

Апскейлинг рендерит кадр в низком разрешении и восстанавливает высокое, используя историю кадров и векторы движения. Нейросети дают лучшее качество, но требуют тензорных ядер; классические методы дешевле и работают везде.

свёрточные сетитрансформерыTAA
01 Суть

Основа — временнáя аккумуляция (TAA): каждый кадр сдвигаем субпиксельный jitter, накапливаем историю и отбрасываем неуверенные пиксели по векторам движения. Простое усреднение размывает; нужны clamp по neighborhood, история в YCoCg и реакция на смену сцены (disocclusion). Апскейлинг — это TAA с апсемплингом и более умным восстановлением деталей.

Нейросетевые методы (DLSS, XeSS) используют свёрточные/трансформерные сети, обученные на паре «низкое разрешение + история → высокое». Они восстанавливают высокочастотные детали лучше эвристик, но требуют тензорных ядер (или DP4a) и обученной модели под конкретный движок. FSR — пространственный/временнóй алгоритм без ML, работает на любом GPU.

Проблемы: ghosting (шлейфы от истории), shimmering (мерцание тонких деталей), disocclusion (объект открылся — история невалидна). Метрики — не только PSNR, но и временнáя стабильность и сохранение деталей; глазами тестируют на траве, сетках, проводах. И всегда есть fallback на нативный рендер и настройка резкости, иначе картинка «мыльная».

математическая модель
out = Σ w(t)·history(t) / Σ w(t), w зависит от motion, depth, luminance
Сдвиг jitter: Halton(2,3) — субпиксельные смещения. Reprojection: uv′ = prev_view_proj · world_pos.
02 Как это построить
  1. Отрендерите кадр в низком разрешении с субпиксельным jitter.
  2. Сгенерируйте векторы движения и буфер глубины.
  3. Репроецируйте историю и отвергните невалидные пиксели (disocclusion).
  4. Смешайте историю и текущий кадр с весами по уверенности.
  5. Выполните апскейл (пространственный или сетевой) и добавьте резкость.
03 Рабочий код
GLSL 
vec3 temporalUpscale(vec2 uv, vec2 motion, sampler2D current,
                        sampler2D history, sampler2D depth, float blend) {
    vec2 prevUv = uv - motion;
    vec3 h = texture(history, prevUv).rgb;
    vec3 c = texture(current, uv).rgb;

    // neighborhood clamp против ghosting
    vec3 lo = c, hi = c;
    for (int i = -1; i <= 1; ++i)
        for (int j = -1; j <= 1; ++j) {
            vec3 s = texture(current, uv + vec2(i, j) * texel).rgb;
            lo = min(lo, s); hi = max(hi, s);
        }
    h = clamp(h, lo, hi);

    float w = blend * (1.0 - smoothstep(0.01, 0.1, length(motion)));
    return mix(c, h, w);
}

05 Где обычно ошибаются
  • История без neighborhood clamp даёт шлейфы за движущимися объектами.
  • Апскейл не заменяет геометрию: тонкие объекты всё равно мерцают без достаточного числа сэмплов.
  • DLSS/FSR нельзя включать для UI и текста без отдельной обработки — они мылятся.
  • Резкость поверх апскейла даёт ореолы; настраивайте умеренно и тестируйте на разных сценах.

Словарь терминов

28 понятий

Термины, которые встречаются в тексте и в вакансиях. Держите под рукой во время технического интервью.

A*
Поиск кратчайшего пути по эвристике h(n): f(n) = g(n) + h(n). Допустимая эвристика не переоценивает остаток.
ECS
Entity Component System: сущность — идентификатор, компоненты — данные, системы — логика. Даёт кэш-локальность и композицию.
DOD
Data-Oriented Design: сначала раскладка данных в памяти под обход, потом код. Основа производительных симуляций.
Fixed-point
Арифметика с фиксированной запятой (Q16.16): детерминирована между платформами, в отличие от float.
Lockstep
Схема, где клиенты обмениваются только командами и считают одинаковую симуляцию; состояние не передаётся.
Rollback
Пересимуляция неподтверждённых вводов после снапшота сервера; основа клиентского предсказания.
Verlet
Интегрирование по позициям: x′ = 2x − x_prev + a·dt². Устойчиво, удобно для ограничений.
PBD / XPBD
Position-Based Dynamics: ограничения проецируются на позиции; XPBD делает жёсткость независимой от итераций.
SPH
Smoothed Particle Hydrodynamics: жидкость как частицы с ядром сглаживания и давлением.
BVH
Bounding Volume Hierarchy: дерево AABB для быстрого отсечения и raycast; строится по SAH.
SAH
Surface Area Heuristic: критерий качества разбиения BVH по площади оболочек.
MCTS / UCT
Monte Carlo Tree Search с формулой UCT: баланс исследования и использования в дереве игры.
Utility AI
Выбор действия по взвешенной сумме нормированных факторов; альтернатива деревьям поведения.
Flow field
Поле направлений к цели на сетке: дешёвый путь для больших групп юнитов.
WFC
Wave Function Collapse: генерация по ограничениям с распространением возможностей и откатом.
SDF
Signed Distance Field: функция расстояния до поверхности; удобна для CSG и ray marching.
Marching cubes
Извлечение изоповерхности из сетки плотности по таблице 256 случаев.
PBR / BRDF
Physically Based Rendering: энергосберегающие материалы; BRDF описывает отражение света.
GGX
Микрогранная модель распределения нормалей с длинным хвостом блика.
Ambisonics
Кодирование 3D-звука сферическими гармониками (W, X, Y, Z) с декодированием под наушники/колонки.
HRTF
Head-Related Transfer Function: фильтр, описывающий, как уши и голова окрашивают звук с направления.
PRD
Pseudo-Random Distribution: шанс растёт после неудач, снижая дисперсию серий без изменения среднего.
Glicko-2 / TrueSkill
Байесовские рейтинги с неопределённостью (RD/σ) и обновлением после матча.
ARIMA
Модель временного ряда: авторегрессия, дифференцирование и скользящее среднее ошибок.
GAN
Соревнование генератора и дискриминатора; WGAN-GP stabilizes обучение через расстояние Вассерштейна.
FFT
Быстрое преобразование Фурье: O(N log N); используется для океана, текстурирования и аудио.
Perlin / fBm
Градиентный шум и его фрактальная сумма октав; база процедурных ландшафтов и материалов.
Кеплер
T² = 4π²a³/(G(M+m)); уравнение M = E − e·sin E связывает время и положение на орбите.
